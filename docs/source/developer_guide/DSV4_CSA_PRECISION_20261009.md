>
> | 真 K | 分支 | 结合顺序 |

> `acc[j] += x[64·splitCount + j]`，仅 lane `j < tailSrcK`，**在所有整块之后、最后一步**。
> 最后一律 `nd_reduce:328 BasicBlockReduceSumImpl`（`splitM ≠ 1` 时 64→8→1）。
>
> **⇒ 门是 `K == 512`。** 本文此前写过的 `K ≥ 449` 与 `K ≥ 481` **都是错的**：
> 前者源于把 `BYTE_BLOCK` 算术反推成 64（字面值是 `32UL`，`scfa_block_vector.h:110`），
> 后者虽用了正确的常量，但误把 `splitK` 当成分支键。
>
> **被这条定稿推翻的结论**：
> - ~~`K = 510` 与 `K = 512` 同结构、`l` 被源码钉死 ⇒ `t62k510 (9,36,321)` 的偏差必在分子~~
>   —— **作废**。`K = 510` 走 (c)、`K = 512` 走 (b)，拓扑不同，该行的 `l` 有自由度。
> - ~~`NewReduceSumLastNDImpl` / `NextBlockAddImpl` / `TailAddImpl` 一次都不会被调用~~
>   —— **全反**。前者每次 softmax 都调；`NextBlockAddImpl` 在 `128 ≤ K < 512` 调；
>   `TailAddImpl` 在 `K % 64 ≠ 0` 调（K = 100/385/416/447/449–480/510 都调）。
> - ~~源码链模型解释 11/14、假阳 3~~ —— 那个模型读的是 BasicBlock 路径，整体作废。
>
> **已对齐、本次确认无差异的环节**（两边都字面读到）：
> 概率 cast native `:482 CAST_ROUND` / 我们 `vconv_f322bf16a`（ties away）；
> 输出 cast native `:854 CAST_RINT` / 我们 `vconv_f322bf16r`（ties even）；
> `l = alpha·l_prev + sum_new` 两边都是独立的 `Mul` + `Add`（非 FMA，native
> `softmax_flashv2_impl.h:470/473`）；种子 `l_prev = 1.0`、`m_prev = sink`；
> **累加次序都是先窗口后压缩**（native `scfa_kernel.h:578-580`：S2 首个内循环必落 ori 段）；
> 除法两边都是先广播分母再 `vdiv`。
>
> **源码位置**（此前缺口）：native 算子在 **vllm-ascend 自己的 `csrc/`**，
> `csrc/attention/sparse_attn_sharedkv/op_kernel/arch32/sparse_attn_sharedkv_scfa_*.h`；
> toolkit 是 **checkout 自带的 `cann-9.2.0-beta.2`**（`$ROOT/Ascend/cann-9.2.0-beta.2/set_env.sh`，
> 由各 run 脚本显式 source），**不是** `/usr/local/Ascend/cann-9.0.0`；
> SOC = `ascend910_93` ⇒ `__NPU_ARCH__ == 2201` ⇒ softmax 实现树是 **`membase/v220`**。
>
> **修法**：K < 512 时对 64 lane 做升序逐元素串行累加、最后一次 64→1 归约。
> 因为我们的掩码列是精确 `+0.0`（`bias = −1e20` 使 `exp` 下溢成精确 0，
> 另有 `csa.py:361` 把 KV tile 清成 BF16 `+0.0`），`x + 0.0` 精确
> ⇒ **不需要 `splitCount`/`tailSrcK` 的运行期逻辑**，按升序把 8 个 64 宽 chunk 全加即可，
> 与 native「有效块串行 + 尾块最后」逐位等价。`K == 512` 保留现有结构（已验 0/1529）。
> **窗口路径一行不动** —— 它现状（`csa.py:546` 的 `vadd(e[j]+e[j+64])` + `vcadd(64→1)`）
> 正好就是 (c) 支的 `acc = b0+b1` 再归约，这正是窗口段一直逐位对的原因。

## 一、结论

| 口径 | 状态 |
|---|---|
| 整层 `output`（18 个验收配置，`actCmpS2Size == 512`） | **18 / 18 `relative_l2 = 0.0`** |
| `heads` 元素级（同上 18 个配置） | **18 / 18 零失配**（`WEIGHTS_OK = 1` 之后；此前 `phase-8196` 余 2 个元素） |
| **短历史档（`K ≤ 511`）** | **未对齐**：shipped 有 **14** 个设备 pre-rope 失配 —— 见**第八节** |

⚠️ 上面两行的「逐位」口径**只覆盖 `actCmpS2Size == 512`**。真实 serving 里
`actCmpS2Size = Min(512, (pos+1)/4)` 取遍 `{0..512}`，短历史请求必然出现；
归约分档的边界是**未对齐真 K == 512**（见顶部定稿块）；`splitK` 不是分支键。

### 第二处修复：weights 投影的 K 切分（`WEIGHTS_OK = 4 → 1`）

`decode_indexer.py:86` 原来把 weights 投影的 K=4096 切成 4 段 1024（每段 64 步 k=16），
再 `((p0+p1)+p2)+p3` 三条 fp32 add；native 的 `ReplicatedLinear` 是
**单一 fp32 累加器、256 步 k=16**。两边都是合法的 fp32 累加，但

- 精确投影 = `0.12036120390985161`，而 `0x3df68000` = `0.120361328125` **恰好是 bf16 中点**；
- 单累加器给 `0x3df68000`（半偶取下格 = native）；4 路切分给 `0x3df68028`，**高 40 个 fp32 ULP**，跨过中点取上格。

**放大链**：40 fp32 ULP → 1 bf16 ULP 投影 → 1 bf16 ULP 的 `w` → **fp16 次正规** coef 的 1 ULP
（次正规区 1 ULP = **1.80%** 相对量；全配置 **69.4%** 的 coef 都是次正规）→
分数偏最多 **6392 fp32 ULP** → **10 对 topk 互换** → mm1/mm2 的 k=16 分组变 →
**2 个 bf16 `heads` 失配**。

**主机门槛**（全 18 配置 26240 个系数）：`WEIGHTS_OK=1` 对 native **26240/26240 逐位**；
`WEIGHTS_OK=4` 是 **26238/26240**，只差 `phase-8195` 与 `phase-8196` 的 **同一个 `t=14 h=24`**。

**设备验收**（36 个 task 全 exit=0）：`heads` 对 native **ON 18/18 全零**、OFF 仅 8196 那 2 个
⇒ **修好 2、新增 0**；`output` 两臂都 18/18 = 0.0；
**410 行逐位比只有 `phase-8196` 的 t=14 变（512 槽里 301 个，ULP 差 −8…−6392），其余 409 行一位不动**；
集合 18/18 零坏行，8196 t=14 对 native 的 topk 顺序失配 **20 → 0**。

生成码：`weights_proj_reduce_vllm.pto` 的 `pto.tadd` **3→0**、`tload` 4→1、
`weights_partial` 视图 1536×64→384×64；`weights_proj_vllm.pto` 内层
`scf.for %d_block to %c2` → **`to %c8`**，8 条 `pto.tmatmul.acc` 全累进同一个 L0C；
外层 spmd 上界 `4*row_blocks` → `row_blocks`。**不需要 `if WEIGHTS_OK > 1:` 守卫**，
四个入口（含非 vllm 的 `indexer_test`）都 `PL CHECK OK` + `CODEGEN CHECK OK`。

性能**测不出可信代价**（两形状符号一致性 5/10 与 4/10 都没过门槛，「候选−空对照」两形状符号相反，
空对照自身地板 −1.48%/+0.65%，80 个绝对中位数跨 0.5826–0.7203 ms）；
**但预言的 +4.5% 被排除**——那在 uniform 上应是 +0.029 ms，实测配对差中位只有 **+0.0008 ms**。

**一个要记的事实**：`phase-8195` 与 `phase-8196` **共用同一组 hidden**（`x` md5 同为 `b65f4a66dd`），
主机门槛对两者都报 `(14,24)`，但**设备上只有 8196 的 scores 动**
——8195 的 `query_scale` 在 `decode_indexer.py:680-690` 的
`head_coefficient = fp32(fp16_rint(query_scale * query_weight))` 处把那 1 个 bf16 ULP 量化掉了。

本次修改在 18 个配置上**修好 6 个元素、新增 0 个**
（`phase-8189`×1、`phase-8194`×2、`uniform-b4`×1、`phase-8196`×2）。
修改前两个失败配置的 `relative_l2` 是 `phase-8189` = 3.6052e-04、`phase-8194` = 3.3952e-04，现均为 0.0。

`relative_l2 = 0` 这个验收标准本身是良定的：`phase-8189` / `q1-` / `w1-` 三代 dump 的
9 个 native 输入哈希与三个输出哈希均逐个相同，native 在输入逐位相同的前提下跨三次独立运行逐位可重复。

> ### ⚠️ 逐位结论的适用口径（必读）
>
> 上表**只在 `actCmpS2Size == 512` 成立**，而全部 18 个验收配置恰好都是这一档。
>
> `actCmpS2Size = Min(512, (pos+1)/4)`（`scfa_kernel.h:373-374`；`sparseBlockSize` 硬写为 1，
> 见 `:235` 与 `sparse_attn_sharedkv_tiling.cpp:825`），取值是 **{0..512} 的全部整数**，
> `pos+1 ≥ 2048` 才饱和到 512。native 的 `l` 归约**按 K 分四档**
> （`softmax_common_nd_reduce.h:297-333`），而第二节那个修复只对齐了 **K ≥ 512** 这一档：
>
> | K = `actCmpS2Size` | 我们 vs native |
> |---|---|
> | 1 … 63 | **逐位相等** |
> | 64 | **逐位相等**（严格） |
> | **65 … 511** | **不等**：32.6%–52.9% 的行（真实数据估 15%–25%），`abs(Δl) ≤ 4` fp32 ULP |
> | 512 | **逐位相等**（= 现有 18 配置） |
>
> 即 `pos+1 ∈ [260, 2047]`（2048 个起始位置里的 **1788 个**）**不逐位**，
> 按 margin 表折合每配置 **1–10 个 bf16 元素翻转**、`relative_l2` 约 **1e-4**
> ——与修复前 `phase-8189` 的 3.6052e-04 同量级。**真实 serving 必然覆盖这一段。**
>
> **窗口块不受影响**：全部 128 个宽度上逐位相等，因为我们在那条 lane 上多加的是
> `exp(-1e20-m) == +0.0`，加 0.0 精确不改值。所以风险面只有压缩块。
>
> 覆盖全区间需要把压缩块改成**跨块带 64 通道累加器**（`pl.range` 的 `init_values` 带
> `[H//2, 64]` FP32 累加器，每块两条 `pl.add` 严格先 lo 再 hi，循环后一条 `row_sum`）
> 再**按 K 运行时分档**（`K >= 512` 走现有 radix-8）。主机已对 K = 1…511 全部验证逐位。
>
> 另一条相关事实：`mte2Size` 缺口**恒为 0**，但原因不是「512 槽恰好全有效」这个巧合，
> 而是两侧生产者都只在**尾部**填 −1（我们 `decode_indexer.py:229-238`；
> native 的排序 arena 初始化成 `(-1e30, -1)` 后降序归并使 −1 全部落尾），
> 逐槽记账下 `mte2Size == actCmpS2Size` 对任意 K 都成立。
> 若将来哪一侧改成在**中段**塞 −1 或放宽候选上界，单条残留 KV 列对 `l` 的扰动是
> **1.6e5–2.6e6 fp32 ULP（2–40 个 bf16 格）**，比归约结合的 ≤4 ULP 高 5–6 个数量级，
> 逐位会立刻变成构造上不可达。

## 二、修复：压缩块的 `l` 按 native 的 radix-8 取分块和

### 定位（零噪声）

把 `m_oi` 在主机上**逐位**复刻成功后才做归因（判据见第五节第 1 条）：
唯一逐位的模型是 **g=16、块内精确、每步只舍入一次（`acc = fl32(acc + Σ_exact(16 个乘积))`）、RNE**，
`phase-8189` 上 1792/1792 = 100%，另外 55 个组合全部 ≤ 90.6%；四个 flip 行 448/448。

在这个复刻件上做 2×2 归因：

| | 我们的 `l` | native radix-8 的 `l` |
|---|---|---|
| 我们的窗口 PV | 基线（= 设备值） | Δ`l` = +2 / 0 / −1 / −1 ULP |
| native 的窗口 PV | Δ`m_oi` = **+0.000 ULP**，0 维变化 | 同上，无叠加 |

**窗口 PV 的 MAD 粒度贡献恰好为零，`l` 的归约树是唯一贡献者。**

### 改动：两处，三条指令

`vllm_ascend/attention/pto_kernels/dspark/decode_sparse_attn_csa.py`：
新增常量 `L_REDUCE_CHUNK = ATTN_K_TILE // 2`，并把压缩块的
`qk_li = pl.row_sum(qk_exp, qk_reduce_tmp)` 换成两条 64 宽 `row_sum` 加一条 `add`。
**窗口块一行不动。**

能做到这么小，靠两条主机全量逐位验证的恒等式（1536/1536 × 三配置）：

- **(A) 连续 64 个元素的平衡二叉树 ≡ `vcgadd(64→8)` + `vcgadd(8→1)`**
  ⇒ 窗口段我们现在的 `row_sum(128)`（同 lane 折半 + `vcadd(64)`）**已经**逐位等于 native 的做法。
- **(B) 8 整除 128，radix-8 的组不跨 128 块**；`ReduceOptFP32_16x512` 的 level-3 平衡树里
  `(v_{2b}+v_{2b+1})` 正好是块 `b` 自己的一对 ⇒ 顶层就是现有的 `(L1+L2)+(L3+L4)` 四路平衡合并，
  **块循环不动**。

所以**不需要 `ReduceOptFP32_16x512` 快路径，也不需要把头通道从 `H//2=32` 改成 16**
（那会是整个 QK/softmax lane 分解的改动）。
`pl.row_sum` 拿到 64 宽 fp32 tile 时，`TryOptimizeFP32Reduce` 的形状门全不满足
（`TRowReduceOps.hpp:242-248`），落到 `OneRepeatProc` 的 `validCol == elemPerRpt` 分支（`:217-221`）
→ `ReduceInstrByMode<true,…>`（`:120-135`）→ **一条无 mask 的 `vcadd`**（`TRowSum.hpp:32-37`）。

不新建 tile：复用已有的 `qk_reduce_tmp`（`:342`），两条 `row_sum` 各写自己的 dst、tmp 纯 scratch。
（**pypto 的 `if` 是 AST 解析成 IfStmt 的，不是 Python 常量折叠**，在分支里
`pl.create_tile` 会被 `SSAVerify` 判成「用在定义 scope 之外」。）

### 生成码与旗标

shipped 路径上实测（臂树对照，两边 `PL CHECK OK` + `CODEGEN CHECK OK`）：
`pto.sync.set 6→6`、`pto.sync.wait 9→9`、`pto.tload 30→30`、`pto.tstore 17→17` **全不变**，

`rows=32, cols=128, v_row=32, v_col=64`。

### 性能：没测出可信代价

臂树 `cp -al` 建、候选文件先断链再打补丁（inode 已核）；
空对照是两份**完全相同**的 shipped 树；同卡配对、按 rep 奇偶换先后、n=16，只比绝对中位数。

| 形状 | 空对照配对差中位 | 候选配对差中位 | 候选 − 空对照 | 候选符号一致 |
|---|---|---|---|---|
| uniform | +0.0011 ms (+0.17%) | +0.0082 ms (+1.31%) | **+0.0072 ms (+1.14%)** | 9/16 |
| varlen | **−0.0047 ms (−0.75%)** | −0.0036 ms (−0.59%) | **+0.0010 ms (+0.16%)** | 6/16 |

两形状符号一致性 9/16 与 6/16 **都没过门槛**；逐样本跨度 ±0.02 ms ≈ ±3%，
远大于 +0.007 ms 的中位位移；**空对照自己在 varlen 上就是 −0.75%**（两条臂是同一份代码），
所以这套测量的地板不是零中心，只能读「候选 − 空对照」，而 +1.1% 与 +0.2% 两形状不自洽
⇒ 仍在噪声里。
算术上也支持近零：每 token 每核多 4 块 × 2 lane × (1 条 `vcadd` + 1 条 `vadd`) = 16 条向量指令，
对 0.63 ms 的内核应在 0.1% 量级。**要分辨 ±1% 需 n ≥ 64 或更安静的机器。**
全部 128 次 run 两条臂 `accuracy_pass = True`、`relative_l2 = 0.0`。

## 三、为什么「只有精确匹配才有净收益」——这条规则成立，radix-8 正是它的印证

定义 `margin_d` 为我们的 fp32 商离**自己所属** bf16 格边界的距离；一个格宽 = **65536** 个 fp32 ULP。

实测（设备值，688128 个 nope 维/配置）：

| margin < | 1 | 3 | 10 | 100 | 1000 | 中位 |
|---|---|---|---|---|---|---|
| phase-8189 | 15 | 66 | 202 | 2060 | 21124 | ~16000 |
| phase-8194 | 10 | 46 | 209 | 2024 | 21107 | ~16000 |
| uniform-b4 | 10 | 50 | 192 | 2035 | 20804 | ~16000 |

全部 27 个 nope flip 维的 margin **max 3.0、中位 1.0**，且在同行 448 维里**排名第 1**
（次小高 50–∞ 倍）。所以：

- **「1 维翻、447 维不变」不是机制，是栅格的选择效应。** 任何 ~1–2 ULP 的扰动——
  行级的也好、逐维独立的也好——都只会翻掉恰好贴在边界上的那一维。
  这个签名**从来不需要特殊机制**，所需分子位移只有 **0.3–1.7 fp32 ULP**。
- **部分修正必然净变差——但这条只对「行级」扰动成立。** 每配置有 46–66 个维
  margin < 3，一个**行级**（分母 `l`、`α`、`a0` 这类同时缩放一整行 448 维）的
  「与 native 不同、但也不等于 native」的改动，会按同样量级扰动全部 1536 行，
  修好 1 个、打坏约 50 个。
  ⚠️ **不要把这条套到逐维的分子扰动上。** 一个只动单个 `d` 的 `m_oi` 扰动没有连带损伤：
  实测那 6 个残余行里，待修维之外的其余 511 维**最小** margin 都在 **25.5–129.7**、
  p1 ≥ 228、**margin < 1 的维数为 0**，而所需位移只有 0.1–1.14 ULP ⇒ 连带翻转为 0。
  混淆这两种口径会把一个本来可行的逐维修法误判成「必然净变差」。
- **margin < 1 的总体极小**（这是栅格选择效应的直接测量值，也解释了全局失配数为何这么少）：
  `t62k510` **9 / 524288**、`s2047` **17 / 786432**，中位 margin 约 16370 / 16391 ULP。
- **radix-8 之所以净收益为正，恰恰因为它不是近似而是精确匹配**：它把我们的 `l` 变成
  逐位等于 native 的 `l`，所以 `m_oi` 一维不动的同时 6 个元素一起归零、新增 0。

这也解释了改动前为何已有 15 个配置全 0：我们与 native 的有效逐维残差**远小于 1 ULP**。

### 4.4 公共链路（全闭）

`exp`（同一条硬件 `vexp`）、除法（同一条 `vdiv`，分母都先 `Brcb` 广播成 8 宽、repeat 同形）、
FMA（两边都是乘+加两条指令，生成码里 `TFUSEDMULADD`/`TAXPY`/`TMULADDDST` 各 0 次）、
两个 cast 模式（输出 CAST_RINT、概率 CAST_ROUND）、BF16 平局规则（同一条 `vconv_f322bf16r`，半偶）、
除法到落盘（除 `scfa_block_vector.h:854` 那条 `Cast`，无 clamp / saturation / 非规格化 / 第二遍）、
inverse RoPE（舍入次数顺序模式全同；四个 flip 维全在 nope 半区，`NOPE_DIM=448`）、
递推步数（两边 `s2LoopTimes=2`）。

**`vdiv` 不是 IEEE 正确舍入**：+0 ULP 94.372%、−1 ULP 3.071%、+1 ULP 2.556%（合计 5.63%）。
两边同指令同输入必同输出，所以这**不是**差异来源，只是**主机复刻件的噪声来源**
——但它曾两次让反解算出错误的门槛（见第五节第 3 条）。

**「native 的 `vdiv` 偏 ±1 ULP」不能解释全部残余，但也没有被排除——它只对两行不够。**
判据是区间检验而非命中率。容 ±1 ULP of `n` 后，源码链模型的 6 个违例里**有 4 个的
`Δm_oi` 区间含 0**（三个 `margin_d = 0` 的中点行，加 `t36k100 (3,30,17)`）⇒ 那 4 行用
已知的除法偏移就能相容；**只剩 2 行**（`t1k385 (7,26,10)`、`t62k510 (9,36,321)`）
在两种容差下都要求 `|Δm_oi| ≥ 1 ULP`。下面这段只对这 2 行成立：
⚠️ **下面这段的前提已作废**：它假设 `t62k510`（K=510）的 `l` 无自由度，而真 K 510 < 512
⇒ 走升序链、与 K=512 的 radix-8 不同构，`l` 有自由度。区间检验本身的算术仍成立，
但「必在分子」的推论不再成立。原文保留如下：
在当时认为 `l` 无自由度的档上放宽到容 ±1 ULP of `n`：`t62k510 t9h36 dim321`
所需的 `Δm_oi` 区间只从 `[+0.8813, +51004.37]` 降到 **`[+0.1031, +51004.37]`**，
**下界仍严格 > 0**，而 `m_oi` 是 fp32、只能整 ULP 地动 ⇒ 结论不变：
native 的 `m_oi[321]` 必须与我们差 ≥ 1 ULP。同时 `s2047` 的 1529 行在 ±1 下仍 **0 违例**
⇒ 这次放宽没有过头，否证本身干净（**上一次**否掉它是把 ±1 套在 `K ≤ 448` 的行上，
那里 `l` 还有自由度、会把放宽吸收掉，所以那次不算）。
附带：用二项分布检验「若 native 的 `vdiv` 与我们同分布」与观察到的失配数是否相容，
结果是**两种假设都相容**（期望翻位 0.506 / 0.957 对实测 1 / 0，p ≈ 0.32–0.37）
⇒ **计数论证在这里没有判别力**，既不排除也不支持 `vdiv`。

## 五、方法论

### 1. 模型误差与待测效应同量级时，主机复刻件不可用

本轮踩了两次：`lsim.py` 在某行偏 +2 ULP 而待测效应也是 ~2 ULP；
mm2 的四个 K 序模型在全部 448 维都给出与设备相同的 bf16 商，其中一维被**四个模型一致**
判到「对」的一侧——那不是效应，是模型自身 14–19% × ~1 ULP 的残差恰好落对了。

**判据：先量模型残差，再量效应；残差 ≥ 效应就必须上设备。**
本轮最终能定位成功，是因为先把 `m_oi` 的复刻做到了**逐位**（1792/1792），
而逐位之所以可能，是因为 `p` 是 bf16 且四行全部 **0/640 个键**够得到最近的 bf16 中点
（已含主机 exp 的 6e-8 不确定度）⇒ `p` 逐位确定，绕开了 `vexp` 最后一位不可建模那条硬边界。

### 2. 不要用主机模型比命中率去推断硬件归约粒度

该方法曾给出「mm1 的 K 序 = 32 步 K=16，命中 73.34%，而 K=128 四步只有 30.61%」，
在 mm2 上重复同法又得 K=16 命中 81–86%——**然后被设备实测证伪为零位影响**。
真实粒度是 **k=16 的 bf16 fractal K0，由硬件决定**，`pl.matmul` 的 tile K 只是描述符。
拟合挑出的只是一群错模型里最不错的那个。

### 3. 反解门槛必须用设备实测的除法偏移，不能假设 IEEE 正确舍入

首版算出 `phase-8189` 需要 `l` 偏 **+2.575** ULP，据此判定 `l` 的全空间（±1 ULP）够不到。
用设备实测的 `off = n_full − RNE(m_oi/l)`（自校验 0/688128 失配）重算后，**+2.000 就够**
——而 radix-8 给的正好是 +2.000。
同类错误还有一次：首版 `flipreq.py` 一律假设「中点 M 归我们、native 必须**越过** M」，
但 `CAST_RINT` 是就近偶数，**native 尾数为偶时 M 本身归 native、只需走到 M**，
而 4 个 flip 里有 3 个正是这种情况。

### 4. 「混合符号」不能用来否掉一个重结合类的机制

首版论断是：4 个 flip 里 3 个要 `l` 变小、只有 1 个要变大，方向相反，
所以「没有单一系统性 `l` 机制能同时满足」。**这条是错的。**
radix-8 **不是系统性偏置，是数据相关的重结合**：Δ`l` 分布近对称
（`−2:28  −1:98  0:1274  +1:116  +2:20`），所以它能同时满足要求反向的行。
四个 flip 行的设备 Δ`l` 是 +2.000 / −2.000 / −1.000 / −2.000，其中三个落在首版自己算出的
纯-`l` 可行区间内。**这是首版把 radix-8 误判为「不是解」的真正原因。**

### 5. 行级杠杆必须全配置计数；「新增 = 0」必须跑满验收口径

`α` 那条在 flip 行自己的 448 维内是「新增 0」，放到该配置全部 1305 个 `α ≡ 1` 的行上是
**修好 1、新增 128**（每行 `m_oi` 变化维中位 287）。
同理「新增 = 0」不能只验 3 个配置——`phase-8196` 的 2 个残差**只有靠 off 基线**
才能判成既有而非新增。

### 6. 探针同步有两个盲区

(a) probe 副本会 drift 而无人察觉——曾有 perf 实验（`PV_N_TILE_WIDE`、tick 轮转、`pv_l1_row=0`）
落进 probe 副本；(b) `pl_check.sh` 只 lower shipped 的 `decode_csa`，**看不见 probe 副本的改动**。
已新增 `bin/opus55-ab/pl_check_kvprobe.sh`（probe 入口）与 `pl_check_arm.sh`（臂树），建议并入标准前置。

### 7. 工具坑

- **查卡**：`task-submit --list`，第一段是 `=== 设备占用 (N/16) ===` / `占用` / `空闲`。
  `cards.sh`（task 内部取 `TASK_DEVICE`）与 `cards.py`（性能对比）都不是查卡的。
- **`--list` 里 Done 行的 duration 含排队时间**，而队列有**约 5 分钟的运行时自动终止**
  （日志尾打 `自动终止`、`exit=130`）。整趟 15 配置的 sweep 与整趟 perf 都因此被砍，
  改成**小批并行**提交后才全部 exit=0。
- 主机复刻件在 **topk 顺序失配**的行上整体失效：必须用**我们的** topk
  （`csa_stages["topk"]`），用 native 槽序会把键挪到不同的 k=16 组、那一行直接 0/448。
- NumPy 2 的 NEP-50 会把 `python_float − np.float32` 算成 float32，ULP 级的差被吃掉；
  bf16 间距必须用**位型 +1**，不能用 fp32 的 `np.nextafter`（小 65536 倍）。
- **臂树命名有歧义风险。** `src/` 下已有 `va-ctl-*`、`va-idx*`、`va-wok1-*`、`va-l1x*` 等
  二十多个臂，新臂起名若与既有前缀撞上（例如 `va-ropecs` 与 `va-rope*`），
  会让「这一臂装了哪个补丁」在日志里不可分辨。**新臂名必须 `grep` 过 `src/` 再用**，
  并在提交任务前用 `pl_check_*.sh` 核对该臂实际装进去的是什么。

## 六、口径与未覆盖

- 全部结论建立在**单层、单卡、合成 hidden、第 2 层 C4 权重**上。
  **没测过** b16、128K、整模型、动态 padding、DP16。
- ~~`phase-8196` 余下 2 个元素是既有残差，本轮未攻。~~ **已由 `WEIGHTS_OK = 1` 修掉**
  （`t=14 h=41 dim=352`、`t=14 h=58 dim=348`，修好 2、新增 0，410 行里 409 行逐位相同）。
  注意该配置 `t=14` 正是 topk 顺序失配的那一行——这是巧合，根因在 weights 投影的 K 切分。
- topk 的顺序失配（28 处 / 5 行，全部「集合相同、仅顺序不同」）属于**排序稳定性**问题，
  不是精度问题：我们的 topk 在少数并列/近并列分数上与 native 的 tie-break 不同。
  它对数值几乎无影响，但会让主机复刻件在那些行整体失效。
- margin 可以做成**上板前的回归预测器**：规则已验证（27 个 flip 维 margin 全 ≤ 3），
  数据已有。任何改动在主机上估一下扰动量级就能预判翻转风险，不必每次赌一轮设备。

## 七、探针

探针全部在 227 未入库的 probe 副本中，五个开关：
KV 行和、分子（`m_oi`/`n_full`）、mm2 的 tile k=128、窗口 PV 的 tile k=128、`l` 的 radix-8。
前两个为观测，后三个是**算法路径改动**。
翻 False 即完全旁路（已实测：`_PROBE_LP_ROWS` 退回 `8*T_PAD*H`，442368 → 196608，
生成码里探针符号各 0 处）。备份还原点在 `bin/opus55-ab/backup-20261009-*`。

**`l` 的 radix-8 已随本文一并进入 shipped 路径**，所以它在 probe 副本里的开关只用于复现历史对照。
mm2 与窗口 PV 两个开关的贡献经实测均为**精确的 0**，保留作反例文档。

## 八、未解项：6 行（短历史档），以及为什么它停在这里

### 8.1 账目：两个必须分清的集合

- **解释不了 3 个**：`t1k385 (7,26,10)`、`t36k100 (3,30,17)`、`t62k510 (9,36,321)`；
- **另外还会打坏 3 个本来就对的**：`k384 (6,19,163)`、`k384 (8,58,424)`、`k448 (10,40,484)`。

容 ±1 ULP of `n`（我们自己实测的 `vdiv` 偏移幅度）后，**只剩 2 行**

**两条独立路径指向同一对行。** 把模型的 `n` 按噪声底扰动做判决稳定性分析，
得到 `6 = 2 decidable + 4 undecidable`，而那 2 个 decidable 的行**正是**上面
±1 除法容差下仍不含 0 的同两行。两条路径互不依赖（一条用除法容差反解区间，
一条用模型噪声底扫判决翻转），结论重合 ⇒ **这 2 行是真未解项，其余 4 行是模型看不清**。

⚠️ **「零假阳性、零假阴性、14/14」这句标定说的是 shipped 判据对设备，不是上面那个 6。**

全部被标出、无漏报。**它不保证源码链模型逐行正确**——事实上该模型就有 3 行假阳性。

#### 4 行是「模型不可判」，不是「模型预测会打坏」

模型噪声底 ≈ **0.015 ULP of `n`**（`r_base` 区间宽度中位 0.0045 + `TOL` 0.01）。
把模型的 `n` 在这个幅度内扰动，看预测的 bf16 桶是否改变：

| # | 行 | 模型 `n` 到两侧桶边（ULP of n） | 判决 |
|---|---|---|---|
| 1 | `k384 (6,19,163)` | **0** / 65536 | 不可判 |
| 2 | `k384 (8,58,424)` | 65534 / **0** | 不可判 |
| 3 | `t1k385 (7,26,10)` | 65533 / 1 | **decidable**（需 ≥2 ULP） |
| 4 | `t36k100 (3,30,17)` | **0** / 65536 | 不可判 |
| 5 | `k448 (10,40,484)` | **0** / 65534 | 不可判 |
| 6 | `t62k510 (9,36,321)` | 65535 / 1 | **decidable**（需 ≥2 ULP） |

⚠️ **「不可判」≠「非设备失配」。** `t36k100 (3,30,17)` 是**真设备失配**
（`margin_d = 1`），但**模型的** `n` 恰好落到桶边 `0x3bb38001 → 0x3bb38000`
⇒ 模型判不了它。所以不可判的是 **4 行**，不是 3 行。

**`margin_d = 0` 的正确含义是「朝某一侧零余量」，不是「落在中点上」。** 两种成因都有：

- 第 2、5 行是**精确中点**：`0x3BAB8000`、`0x3B988000`，bf16 尾数 LSB 为**偶**，
  半偶把中点判归本桶 ⇒ 本桶含该端点 ⇒ 余量 0。
- 第 1 行**不在中点**：设备 `n_full = 0x3c4d7fff`，中点是 `0x3c4d8000`。但 `0x3c4d`
  的尾数 LSB 为**奇**，半偶把中点判给 `0x3c4e`，于是 `0x3c4d` 桶的含端点上界恰是
  `0x3c4d7fff` = 设备值 ⇒ 到上界余量 0。**不是显示截断、不是 float64 混用。**

后果相同：**待判效应量就是 0**，而模型已知带 `vexp` 末位不可建模与 `vdiv` ±1 ULP
两个噪声源。这是 §五.1 那条规则的极端情形 —— **设备是唯一仲裁者。**
（链补丁的设备验证在进行中；结果按三种情况分流：新打坏 0 ⇒ 结构读对了、净修 11 可落地；
新打坏恰为那 3 个坐标 ⇒ 结构接近但不精确，这 3 个坐标就是下一轮的判据；
新打坏是别的坐标 ⇒ 模型与设备脱节，停下来别自己修模型。）

### 8.3 唯一没被直接测量的对象，以及它为什么测不到

清单里每一项都是「设备实测」或「源码钉死」，只有一个例外：
**native 的 `l`（以及 fp32 `m_oi` 累加器）本身，我们从未在设备上读到过它的字节。**
~~`K ≥ 481` 档「`l` 与我们逐位相同」~~ —— 该档划分本身已作废（分支键是未对齐真 K）。
真正的状态是：**native 的 `l` 从未在设备上被读到过**，而它的结构已由源码读定。

唯一看起来可用的读口是 `npu_sparse_flash_mla(..., return_softmax_lse=True)`
（`vllm_ascend/attention/dsa_v41.py:505`）。**它没有分辨率，不要再试**：

- 写出来的是 **`ln(expSum) + max`**（`scfa_block_vector.h:409-411`，`ProcessLse`，
  由 `:738-739` 在最后一个 s2 分块时调用），fp32 但是**对数的**，
  不是原始 `expSum`、也不是分开的 `softmaxMax`/`softmaxSum`；
- 实测 `l ∈ [104.85, 313.10]` ⇒ `ln(l) ∈ [4.65, 5.75]` 落在 fp32 binade `[4,8)`、
  ULP = 2⁻²¹ = 4.7684e-07；`l` 动 1 ULP 只让 LSE 动 **0.125–0.25 ULP**
  （`t9h36` 具体是 0.162）⇒ **要让存下的 LSE 动 1 个 ULP，需要 `l` 动 4–8 个 ULP**，
  而待分辨的是 **0.09–1.0 ULP**；
- 再叠上 `Log`（`:409`）与 `Add`（`:411`）各一次 fp32 舍入（各 ±0.5 LSE-ULP = ±2–4 l-ULP），
  **连差异的符号都取不回来**。

附带结论：打开该开关只多一个 1K buffer 与一组同步旗标（`:210-212`、`:407-416`），
不改 `splitK`、不改归约结构、不改 L0C 复用 ⇒ `output` 比特不变。但这已无意义。
