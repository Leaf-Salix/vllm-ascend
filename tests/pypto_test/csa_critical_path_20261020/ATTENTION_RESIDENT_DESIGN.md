# 降低发布区峰值，使 64KiB 独立 KV 供数缓冲具备编译条件

本候选目前只做 CPU 资源可行性检查。正式源、Key 负例和正在排队的
Score 背压诊断均不修改，也不据资源估算提交第二轮设备测试。

## 关键路径与相对旧候选的变化

当前诊断的 B28 AIC 等 KV 区间约186.50μs，但不等于可直接消除的开销。
原64KiB独立缓冲候选E45因为UB需要202240/201472B，超过188416B而停止，
没有做真机完整测试。E46改成32KiB、每lane分两段供数，B16仅快4.48μs，
B24/B28回退，未采用。

这次先删除最终发布处的512列FP32拼接临时量：分别归一左右256列，
最后只拼BF16。每个元素依然执行同一FP32除法，分母不变，不变成倒数乘法；
逆RoPE读取右半行的FP32归一值，修改的仅是其局部索引行距。softmax、
online m/l/oi归并、FP32/BF16边界不变。预期降低临时量峰值，使64KiB
独立KV区与数学临时区同时存在，避免32KiB版本分两次供数。

独立KV与数学临时区不共址可能减少MTE2/MTE3与Vector的串行复用，这是
候选希望缩短的路径。不会把186μs或MGATHER包围区间当作确定收益。
也不把少一个concat当成独立的20μs性能承诺。

## 停止条件与验证边界

1. 首先只编译B28所用的动态资源策略，不提供batch/历史样例shape。
2. 真实分配仍超限、动态别名/槽保护不成立，就保留失败并停止，不增加硬件容量。
3. 若资源审计通过，仍需当前背压诊断决定下一项优先级；不自动扩展设备任务。
4. 真机若验证，继续完整精确和20μs代表档门槛；未通过前不迁入正式代码。

`prepare_attention_resident.py`核对E46的参考Attention AST与当前正式一致，
仅重用其显式DMA/无效行补零表达，保留当前其余36文件。数学等价性仍须
完整设备验证；本地1024项整数RoPE索引映射不是精度通过的替代。

## CPU结果：仍超限，本候选停止

`cpu_attention_resident_b28_v1`在 AllocateMemoryAddr 阶段失败：Vec需要
201472B，硬件上限188416B。保留58个动态轴，没有传样例shape。删除FP32
整块拼接并没有降低本次编译器最终报告的峰值；不能仅凭源码少一个临时量
就宣称资源已优化，也不能据此认定是编译器bug。按照预先停止条件，不上卡、
不改硬件上限、不继续扫描更小发布tile。本轮正式37文件保持原版。
