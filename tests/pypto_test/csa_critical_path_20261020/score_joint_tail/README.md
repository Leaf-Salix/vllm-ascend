长G6/N64/1024、预取到L0资源域，step剩余1..64个候选时，原16个N64

减少总工作不等于减少关键路径，不能承诺固定微秒或与旧列池收益相加。

先完整CPU核对B28，再验证B28完整三方五窗。若相对当前正式不足20μs，

随后按原目标覆盖其它区间、S1/S5及边界。最终五档30%目标没有缩小。

## 首次编译失败与修正

cpu_b28_v1在前端拒绝短尾4列TGATHERB索引，接口要求UINT32索引行是8列
整数倍。候选编写未遵守接口，非组件bug，未发issue或改依赖。首版完整源
保存在source_candidate_v1。v2利用短尾至多两页的数学资源合同，仅在逆序
且恰两页时交换两个32元素FP16片段；一页保留已填零结果，整块原路径不变。

v2前端随后发现两分支Tile的pad类型不同：原连续页是PadValue.zero，
交换结果缺少该属性。v3对完整有效交换结果保留同一zero属性，数值不变；
这是源码类型合同修正，未改编译器。source_candidate_v2与失败输出保留。

v3通过分配但被既有lowering保护拒绝：Acc列池slice结果不能再用
set_validshape收窄成六行。v4按接口要求在store用slice的valid_shape明确
六行范围；没有绕过保护、没有增加Acc搬运或修改依赖。v3全源和IR保留。

v4到PTOAS后遇到历史已记录的A3 Vec窄列assemble限制：32→64宽
和64→1024宽不能按父Tile stride做TMOV。v5将逆序页缓冲解释为2×32，
将segments临时解释为96×64整行视图，然后恢复原6×1024；元素偏移保持，
不增加GM或业务数学。v4全源与失败PTO保留，未放宽PTOAS检查。
