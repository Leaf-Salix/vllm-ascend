# 当前双QK早FIX与原布局WS列池组合

正式13259f92的Score生产链仍是较大阶段；新PMU显示B28 AIC FIX聚合占用
约328μs，但它含全层及资源等待，不等于Score可省时长。当前每1024个候选
有32次QK FIX及16次六行WS写回。候选不减少必要QK/WS数学，而把小WS写回
批量化：八个16×64结果直接累计到16×512 Acc列池，再写原GM的六行512列。
两个512列覆盖原1024列FIFO，READY/ACK时刻与布局合同不变。

## 与旧负例的实质区别

旧score_native_layout_acc_pool_20261019只在原单96KiB QK Acc下测B16，
809.86→806.58μs，仅2/5窗更快，未采用。本轮保留已经采用的两份48KiB
QK早FIX和分K192累计，WS32KiB池与它们并存，合计128KiB。提前QK FIX已
改变大块转换与小WS写回的排队关系，所以这是新组合，不复述旧3.28μs
为新收益。当前无独占FIX事件耗时，不能承诺16→2等于固定微秒收益。

旧N128改过面板宽度和预取，旧wave新增Left恢复，本候选两者均不做。
保持N64/两Key槽、原Mat/Right预取、当前FP16舍入/ReLU、六行系数的两段
K192顺序、AIV连续scale/排序/Top-K、整步通知/双槽ACK及全部页/尾行保护。
只沿现有SPLIT_SCORE_ROWS资源域启用，真实T/B/有效历史/位置/页表仍动态，
无新增Host值、外部适配、根Tensor、单点策略或Mat中转复制。
