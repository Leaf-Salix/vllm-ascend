此文是下一候选设计，尚未实现/编译/上卡。当前列池单独组合只有B16/B28
5.42/12.12μs收益，未达到20μs，保持正式13259f92，不继续扫池宽。

面板，其余Cube路径/FP16边界/FFTS/AIV排序不变。B16/B24分别820.12/
1127.60μs，没有现选同进程A/B，未采用；不能将它描述成从未测试的想法。
历史范围与结果见INDEXER_SHORT_TAIL_EXPERIMENT.md和统一日志07:43段。

若继续，实质变化必须是当前双QK早FIX与已编译列池，加上生产/消费一致
的短尾路径，而非原样搬旧单M384 QK。仅在当前已有长G6/N64/1024资源域、
本轮device step有效数为1..64时进入，不按B16/B28或131072写白名单。

- Cube保留当前两半QK及K192+192 WS，只处理前N64；原有效query补齐、
  页表/末页钳制/0或64B视图选择及两次FP16转换均保持。每步仍一次READY，
  两AIV仍各一次ACK和原leaf drain，不能因为短尾删事件或伪造完成。
- AIV也只加载Cube已写的前64列，缩短scale和乘法准备。不能跳Cube后960列
  却继续读取这段未写GM。原segments整块NEG_INF初始化和每条query实际
  visible裁剪、tiny/small/large排序及同分优先顺序保留，不改变根ABI。
- B28当前scale合并路径已经只读尾部真实页；短尾应保留该合并读取，不能
  退回两次逐页Scalar/DMA后再声称减少所有scale搬运。B16关闭合并证明，
  才有逐页32次→最多2次的实际候选空间。
- 生产与消费必须使用相同资源开关/实际valid来源。需要将已有SPLIT选择
  接给Vector时只传既有constexpr，实际长度仍在device；注意不同Tile形状
  不跨分支强行合并，保持公共segments父Tile及初始化合同。

NEXT_TAIL_WORK_MODEL.json仅重读已通过wave用例的真实group metadata；
其group规则文件与当前逐字相同。B16最大核面板数352→352（只有部分核
减少），B28 656→641，全核分别少240/420个N64面板。不能按总数减少就
保证B16提速，或把模型与本轮列池12.12μs相加称为可兑现20μs。

因此下一实现若有合理资源合同，优先在B28检验这个更完整组合，再按
20μs/另一档无明确退步门槛决定后续范围。仍须同轮原多task/正式/候选，
不将未采用列池换成正式reference；保护、metadata/padding/图/代际不变。
若资源表达复杂且缺乏合理收益上限，或B28完整收益不足，就结束，不继续
围绕tail宽度扫描。正式源、依赖仓以及等待策略均保持，未经允许不得push。
