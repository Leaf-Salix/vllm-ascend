继续优化 DeepSeek-V4 Flash 的动态单 SPMD CSA 算子，使 128K 五档相对原 PTO 多 task 实现的完整 L1 耗时降低至少 30%，同时保证 8K 两档没有明显退步。

一、目标与优先级
- 128K：B4、B8、B16、B24、B28；优先攻克 B16、B28，再覆盖其余三档。
- 8K：B16、B32，兼顾性能与回归。
- 主要性能场景 S=6；S=5、S=1 验证精度和动态范围。
- 使用正式权重 /data/model/DeepSeek-V4-Flash-0731-w8a8。

二、计时与验收
- 使用此前 CSA 的完整算子测试方式。
- 多 task 与单 SPMD 均统计 L1 中最早 incore task 开始到最后 incore task 结束，保留区间内的等待和调度间隙，不计区间外的启动、收尾开销。
- 候选与当前正式版本、原多 task 在同轮条件下配对测量，不拼接不同轮次的最优值。
- 30% 目标按（多 task 耗时－候选耗时）÷多 task 耗时计算。
- 展示数据时保留 Native、多 task 含 AICPU、多 task L1、历史静态 SPMD、动态 SPMD 的口径区别。用户要求的“提升比例”另按（基准耗时－动态耗时）÷动态耗时计算。
- 未达到目标不得宣布完成；局部阶段加速不能代替完整算子收益。

三、优化方法
- 先完成一轮有明确证据的 B16/B28 关键路径诊断，再确定候选收益门槛。
- 优先优化占比大的计算、搬运、重复工作和串行依赖，避免长期围绕微小开销调参。
- 结合真机阶段时戳、全核 incore 流水和实际生成代码定位问题；模拟只辅助解释，最终以真机结果决定采用。
- 每个候选明确：缩短哪段关键路径、依据是什么、潜在收益以及停止条件。
- 允许基于新证据重评历史负例，但先说明与上次的实质区别。
- 当前 SDMA 三种方案均无净收益，先转向其他优化；保留其缺陷复现和修复草稿，有新证据再评估。

四、实现边界
- 最终仍是一个完整 SPMD CSA 算子。
- 正式动态实现位于：
  vllm-ascend-dsv4-pto-0251rc1/vllm_ascend/ops/pypto/deepseek_v4_flash_csa_spmd
- 可以增加有依据的历史长度、batch/token 数及输入序列长度区间策略；禁止按验收点增加单点特化。
- 档内保留实际长度、位置、页表、有效行和循环范围的动态计算，不要求一份二进制覆盖所有 batch。
- 可短程尝试独立 metadata 作为诊断；若收益重大再讨论最终分离，不能在此方向耗时过久。
- 允许修改独立 worktree 中的 PyPTO、Simpler、PTOAS，不能破坏共享安装或其他会话工作区。

五、正确性与验证
- 保持现有数值、cache/state、保护区、metadata/padding、图重放和同步代际检查。
- 默认保持当前数学语义；数值等价但非逐 bit 的数学优化，采用前另行确认。
- 先验证代表档；有明确完整收益后再扩档，并覆盖受影响区间边界及 S=1/S=5。
- 避免无依据重复全量测试，不修改真机同步协议来迁就模拟器。
