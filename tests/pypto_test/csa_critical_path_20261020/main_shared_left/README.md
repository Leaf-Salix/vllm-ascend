# 主Compressor两路投影共享Left输入

基于正式13259f92/source_after_score_split，只调整主Compressor的资源表达。
当前阶段诊断主投影非外层GM等待中位B16约37.89、B28约57.84μs，处于
Score前串行生产链；这不是全可节省时间。实际完整IR显示主M64/N64/K512
的value、gate各自进入后端K256拆分，两者重复从同一Mat恢复两份32KiB Left。
Indexer M16/N32/K512已经共享同一Left，保持不动，也不重复旧Indexer双槽负例。

候选将主投影的源码K改为256，保留同一个x_tile给value/gate。后端若能像
Indexer一样复用Left，则每K512的输入Left搬运从四次减少为两次；每个输出
依旧按K=0,256,...,3840累加，共16次MMA，没有跨K重排、split-K或精度改变。
依旧使用首块matmul建立动态compact有效行，不能用固定64行零种子替代。
原M64/N64、输出owner、stage=2、写回及跨核发布获取保持。所有T/B/页表动态，
不是B16/B28白名单；没有新增外部适配、权重转换或工作区。

这与旧主QB权重常驻、旧Indexer M16的显式Right双槽不同。预期缩短的是主
投影的重复MTE1与相应串行等待；实际Left共享、Right活跃数量、双缓冲与
compact属性必须在完整编译产物核实。不能仅按理论字节数声称净省20μs。

先两种当前完整策略CPU，若未减少重复搬运或引入不合理资源膨胀则停止。
机制成立后按原完整三方五窗与冻结精确/状态/保护/metadata/padding/图/代际
门槛验证代表档；至少一重点档净省20μs且另一档无明确退步才扩档及S1/S5。
不放宽数学门槛，不以局部加速替代完整收益。正式源码与隔离依赖未变。
