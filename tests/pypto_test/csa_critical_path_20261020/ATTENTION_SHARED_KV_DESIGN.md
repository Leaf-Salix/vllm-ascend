# 独立64KiB KV供数区：互斥路径共址与逐元素归并降峰值

## 范围和优先级

前一目标轮完成Q_B流式驻留完整验证，结果改变后续行动，属于有进展；
没有待处理设备任务或真实外部阻塞。正式37文件重新核对仍为E49，本轮
继续128K五档相对多task完整L1降低30%的目标及20μs扩档门槛，未push。

当前B28 AIC等KV的Scalar观察中位约186.50μs，每核35个有效块；它包含
AIV前拍数学、搬运和协议，不能全部视为可消除的供数时间。正式MGATHER
与数学临时量共用UB，ISA内部另有保守的V/S及MTE同步。候选的目标是把KV
DMA与数学临时区分开，尝试让两条流水重叠；最终仍看完整L1而非局部收益。

## 历史方案与这次的实质区别

E45/本目录source_attention_resident的64KiB专用区因201472B超过真实
188416B而停止，未有完整真机结果。E46使用32KiB并将一次64行拆成两次
搬运，B16小幅改善但B24/B28回退，已结束，不能重新包装该结果。

本轮首先考虑过拆开row_max/row_sum共用的16KiB scratch，但只读检查
没有支持它是峰值主因，没有修改或编译这个假设。旧MemoryReuse实际类
容量之和恰为201472B；其中专用KV 64KiB、SWA/逻辑回退KV 64KiB以及两份
32KiB在线oi状态是不同类，另有4096B RoPE索引及768B小项。证据见
ATTENTION_SHARED_KV_OLD_ALLOCATION.json。

第一版让互斥的压缩/SWA/逻辑回退共用一份专用KV：SWA先对同址Tile设
零有效行，再调用既有fillpad_inplace填满正零。不能用旧值乘零，旧UB
可能含NaN；也不创建另一份完整零Tile。页run、逻辑guard、最终写出及
跨拍MTE3读完才能改写的依赖保持。

cpu_attention_shared_kv_b28_v1再次报告201472B。IR已证明KV两路径同址，
但第二个64KiB类被PV归并的两个32KiB类取代：pv_left/right载入与
old*alpha乘积同时存活。因此，共址表达修正有效，但并未解决全部峰值；
不能把不变的总数解释成fillpad_inplace不生效，也不能称为编译器bug。

## 第二版的数学和资源合同

source_attention_shared_kv_merge16在第一版基础上，仅将逐元素oi更新
按既有FINAL_HEAD_TILE=16头做两段。每头每列仍按`old*alpha + pv*beta`
计算，不改FMA策略、不拆跨列归约、不改row_max/row_sum与在线m/l计算。
两段写回同一完整32头状态，后段读取自己的未更新行。列向量切片沿既有
最终发布的reshape/extract表达，避免丢掉后16头偏移。

这是资源表达改动，不是把16头设成batch验收点。T、有效mask、KV索引、
地址、页保护和所有循环仍动态；一个完整MIX，原FFTS和通知代际不变。
源级整数覆盖16384个(head,column)元素只检查覆盖，不替代设备精度。
最终左右256列分别除同一分母，沿用前一资源候选的等价表达；其设备
精确性仍须完整验证，未提前宣称通过。

## 停止条件

- 第二版若仍超真实UB容量，或出现无法合理消除的完整状态复制/别名冲突，
  结束本资源尝试，不扫描更小头块、不提升188416B上限。
- 编译通过后先审查同址KV、数学临时区分离、真实16头运算和同步事件，
  再跑B28完整三方五窗，随后按需要验证B16。只过CPU不算正确性通过。
- 至少一个重点档相对同轮正式完整L1净省20μs且另一档无明确退步后，
  才扩其它档和动态边界/S1/S5。失败则保存证据，不迁入正式源码。
- 继续原数学和所有冻结精度、cache/state、保护、metadata/padding、图
  重放、代际检查，不以任何局部计时替代完整收益。没有组件修改或push。

当前第二版编译目录：cpu_attention_shared_kv_b28_v2，尚无资源终态或设备结果。

## 16头DPS版终止，另做独立状态表达

第二版cpu_attention_shared_kv_b28_v2超限214016B，未上卡。实际MemoryReuse
显示，分段assemble更新32头父状态引入left_iter_mv/right_iter_mv及相应
回传保护复制，各32KiB；不是仅有两个16KiB工作块。已结束该表达，不继续
扫描8头或4头，完整分配记录在ATTENTION_SHARED_KV_V2_ALLOCATION.json。

另建source_attention_state_halves，保持同一个16头数学宽度，但把跨拍oi
状态本身改为left0/left1/right0/right1四份16KiB，各自用原函数式
row_expand_mul/add更新和loop yield，不对32头父Tile做DPS写回。最终
发布直接选择对应半段；32头softmax、m/l、归约和FP32/BF16边界不改。
新表达意在消除父状态保护复制，而非放宽内存约束或改变算法。若这份
完整CPU仍超限就结束整个资源方向，不再继续拆头。当前CPU目录
cpu_attention_state_halves_b28_v1，尚无结果；所有正式源与依赖未改。

## 四半段状态版本资源通过，进入两个代表档

cpu_attention_state_halves_b28_v1与b16_v1均完整通过58动态轴/单MIX。
实际UB上界分别181248/182016B，低于真实188416B。两路径KV所有别名
同一64KiB；四份oi各16KiB、互不覆盖，next与本份初始状态同址；循环内
不存在>=32KiB整状态move，归约仍仅原row_max/row_sum两次。原地填充
生成TFILLPAD<InPlace>，保留前拍MTE3→V依赖，零有效行也在IR中保留。
首版审计误找TFILLPAD_INPLACE函数拼写和已被消除的kv_empty注释，已按
实际模板写法修正；这是审计脚本错误，非编译或设备错误。

完整三方五窗任务：B28 task_20261020_043919_14214894072，B16
task_20261020_043934_14322076168。任务期间冻结候选源与工具链。两档均
包含A→B→A、metadata/padding图和代际检查，尚无设备终态或收益结论。

只读审计发现索引256B临时区与部分Vector临时区共址，记录在
ATTENTION_STATE_HALVES_INDEX_ALIAS.json；这不证明新的关键等待。实际
索引TLOAD前主要看到S→MTE2边，尚未追清可能的间接V依赖，因此未将
这个地址共享当成已证实瓶颈，也没有修改正在运行的候选或追加测量。
