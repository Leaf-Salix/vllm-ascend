# 候选：Indexer 每个分数块集中准备 Key

## 证据与变化

当前 B16/B28 Score 阶段分别约 200/360 微秒，是最主要服务区间之一。
旧 PMU 显示 MTE1、FIX、矩阵时间相互重叠，不能简单归因带宽。本候选不改
这些数学；将各 N64 面板之间的页解析与 GM→L1 指令集中到当前 1024 块开头，
之后维持原 QK/current + WS/previous 的执行次序和 L0 预取。

历史 INDEXER_KEY_POOL_CPU_EXPERIMENT 仅扩大池且保持 DMA 发射位置，
没有减少同步、未上卡；本次的实质区别是移动所有 32 页的 DMA 发射位置，
并使用当前已验证的 L1 物理范围分析工具链。

## 潜在收益与停止条件

目标是减少 QK/WS 热循环被 Scalar 地址准备及 MTE2/MTE1 交接打断的时间。
先核对生成物确实是32页准备后再做16面板。仅凭指令数不预计确定收益。
128KiB L1可能挤占其它阶段或让搬运不能覆盖计算；若CPU资源/地址审阅不过，
不提交设备；若B16/B28完整配对无稳定收益，不扩其余档，不继续扫池大小。
完整数学、分片、页界/负页保护、动态形状、通知/等待和精度门槛全部保持。

CPU v1 在DSL类型推导阶段拒绝同名Tile在两分支具有不同静态盒子，未执行设备。
改为单一create的constexpr形状表达式，保留原始失败。v1目录含b16字样但
实际controls为B28对应资源区间，以下以controls JSON为准，不按目录名判断策略。

v2的条件表达式被当前DSL拒绝（IfExp不支持）；没有把它报告为组件bug。
v3改为两个由Host策略计算的constexpr资源参数KEY_L1_SLOTS/KEY_PRIME_PANELS，
默认2/1保留原调用，长balanced使用16/16；设备Tensor轴、页址与有效循环不变。
CPU始终不提供实值样例shape。

v3把未预取回退的临时Tile定义移入分支，SSA校验正确拒绝后续跨作用域使用。
v4恢复共同定义，只移动加载部分；长历史未使用的局部Tile由DCE处理。
这两次CPU失败属于本次算子写法问题，不作为PyPTO bug提交。

真机精度；设备任务仍使用原handle等待，没有据误判重编或取消。
