# 无后继短任务：去掉 Wait 的控制字段读取，开销仍未清零

**最新决定：用户接受必要的固定开销，暂停追求零开销。保留 PyPTO `320beb494`、
Simpler `66d6ce63e`、PTOAS `4a5ce22a` 的指针交接位候选，后续以它为基准审查其他开销。**
它在有效功能候选中具有较低的单核额外时间，不将不同轮次的数据排名写成绝对最优。

接续过程 044。只使用私有 TMR、CANN 9.2、单卡 0；没有新测 CSA/HBG/整模型，
公共安装与算子没有切换。保持原 dispatch、选核、ACK 流程及用户的 early-resolve 设置。

## 两个内部传参候选

1. Simpler `946011175`：给支持局部 Wait 的物理入口增加第二个 Scalar 参数，
   直接传递 executor 已知的交接状态。它去掉 Wait 的 GM 标志读取，但执行器需要判断入口 ABI。
2. Simpler `66d6ce63e`：恢复原有单指针物理入口；只在实际交接的原有 ACK 分支中，
   用已对齐 args 指针的低位传递状态。编译器先清除该位再访问 args，并把状态传给内部 Wait。
   普通执行器路径不做 ABI 查询；被标记的 kernel 入口仍有解码与条件判断。

两版都不改变算子作者写法；局部 Wait/Set 保留。只有真实交接进入完成回调，
无后继仍由 executor 做原 PIPE_ALL 等待。新路径不再写回 LocalContext 的热行标志，
旧 demo 接口继续兼容。PTOAS 只改局部 Wait 的参数转发，Scalar 前缀保留机制未变。

`marked_memory_wait` 是同 SDK 的旧热行读取诊断控制，只能用于本无后继图，
不能作为真实交接实现。它同时包含当前 wrapper 的参数处理，因此不是旧版本完整运行时的基线。

## 过程046：冷函数检查及最终选择

尝试将回调放进独立冷函数，普通入口根据交接位选择路径，两个计算主体由同一 lowered task 生成。
CCEC `-fstack-usage` 显示：普通短任务栈帧0字节，指针交接位版本64字节，冷函数版本普通入口16字节、
交接入口64字节。`[[clang::musttail]]` 编译成功但入口仍为16字节，没有保留这一无效修饰。
栈帧差异证明代码生成受影响，不能单独证明全部时间差都来自寄存器保存。
对应 `*.su` 保存在本目录，编译参数沿用私有 KernelCompiler 的 flags/includes，额外增加 `-fstack-usage`。

任务 `task_20261011_150410_169423030812`，同卡同SDK，每版30次，3项设备功能通过；
单block记录60/60完整。单位μs：

| 口径 | 普通 min/mean/max | 冷函数 min/mean/max |
| --- | --- | --- |
| 单block核内 | 1.340/1.485/2.100 | 1.400/1.747/2.240 |
| 48-block单次Event | 96.400/103.807/113.640 | 98.200/104.258/111.840 |
| 48-block图内32次均摊 | 70.690/71.858/73.840 | 69.208/70.864/72.342 |

冷函数核内仍多0.262μs，二进制文本456→752字节。均摊口径有改善，不能据此认定所有路径改善，
也不能跨轮将它与指针交接位版作精确排名。基础AIV两轮重叠28/48、48/48，AIC为8/24、24/24。
任务退出0，卡已释放。随后开始编写的独立物理双入口方案尚未构建/上卡，用户收敛要求后已撤掉。

保留指针交接位版的依据：真实交接已验证，普通Wait无需GM标志读取，真实交接不新增热行写回，
单核额外时间记录较低，代码体积小于冷函数版。所有未验证的双入口修改和冷函数改动均已退出工作树；
源码与已安装私有二进制重新对应上述三个提交，公共安装未切换。

后续只审查其他协议开销，优先看：

1. Wait回调已清理并写回控制行，而同步后继返回时再次写回；先核实无trace/无后续控制写入的范围。
2. 候选资格检查前就执行全D-cache操作；审查能否先同步必要控制行，只在确认交接后处理参数可见性。
3. executor与完成等待helper重复读取volatile tail/trace字段；复用已读值，保留全部原等待与诊断语义。

以上是源码审查得到的候选点，尚未测得收益，不改变已dispatch要求、原ACK流程或用户early-resolve设置。
