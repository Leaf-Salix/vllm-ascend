# 无后继短任务：额外开销定位，尚未清零

目标是保持原派发、ACK、`allow_early_resolve`、数学与流水策略，消除没有实际交接时的额外开销。
本轮只做私有 TMR 单卡诊断，没有新测 CSA、HBG 或整模型，也没有切换公共安装。

保留的实验候选：Simpler `0de0c4c62`、PyPTO `4a23fb1e9`；PTOAS 仍为 `d53e3af3`。
初始定位使用上一候选的 Simpler `a9edc8455`、PyPTO `d8e8e5935`。
均为 CANN 9.2、0 卡。不能跨轮次直接相减绝对时间作为优化收益。

## 计时范围与初步归因的修正

- 单次图的 Event 由 Host 分别提交 start、replay、end，短图时间会受到提交空档等影响。
  原先短图的 +4.11 μs 不能全部归给单核交接协议。
- 增加同图内串行调用 32 次、Event 时间除以 32 的诊断口径。它摊薄提交成本，
  也改变缓存和启动条件，不能将两种口径之差直接当成 Host 开销。
- 首轮 48-block 因子对照：批量均摊普通 70.985、Wait 71.977、Set 71.206、
  Wait+Set 72.109 μs。后续空回调控制对照没有稳定复现该幅度，撤回
  “据此已定位约 1 μs 间接调用成本”的推断。
- 48-block 核内采集仅有 1881/1920 条记录，并受到并行访存等影响，不用于严格成本归因。
  改用 `spmd(1)`：全图只有一个 block，严格没有同核后继；单核读取 32×256 FP32、
  一次加法、写回。三个单 block 采集分别完整得到 120/120、90/90、90/90 条记录。
- 核内窗口为已有 level-1 chip swimlane 的 start→end，含 kernel 和 executor 排空，
  不含 Host 提交。DFX 会禁用实际交接探测，所以它不能单独证明非 profiling 路径的尾部探测零成本。
  全部原始 Event、核内窗口和复算脚本保留在本目录。

这些时间差不能简单相加，Scalar 与流水等待存在重叠。

## 保留的私有候选：从派发热行判断是否实际交接

`AsyncCtx` 原有 4 字节对齐空隙保存 `local_predecessor_pending`；没有增加
`AsyncCtx`、`LocalContext`、`DispatchPayload` 的大小，也没有改变旧字段偏移。
普通 dispatch 归零；AICore 只在真实进入已经正常派发的后继时置位。
Wait 先读 LocalContext 的热行，仅置位时追踪 GlobalContext 并调用原完成回调。
真实交接完成后清零并在 FIN 前写回热行；无交接时 AICore 不写该标志。

代价也明确保留：真实交接路径增加一次热行写回，尚未证明该路径的净性能改善。
这只是减少无交接开销的私有候选，不能当作整项性能验收通过。

CPU 调度器 9 项、定向 codegen 3 项、设备基础功能 3 项通过。
输出/保护区正常；两轮 AIV 实际观察到 18/48、48/48 条同核 Scalar/全流水重叠，
AIC 为 24/24、24/24。仅证明基础动态交接，不能换算为 CSA 交接率或性能收益。

## 未保留的两个尝试

1. 移除 Wait 开头重复的 memory clobber：两个短用例的生成机器码均不变。
   因此没有重复上卡；生产候选保留原屏障，仅保留诊断开关。
2. 将同一 runtime 完成回调内联到 incore，消除间接调用。任务
   `task_20261011_140154_300542529112`，单 block 各 30 次，单位 μs：

| 版本 | min | mean | max |
| --- | ---: | ---: | ---: |
| 普通 | 1.320 | 1.468 | 2.100 |
| 热行标志 | 1.380 | 1.536 | 2.120 |
| 内联回调 | 1.360 | 1.537 | 2.180 |

内联没有收益，kernel 文本从 456 增至 856 字节，因此不接入。
初次内联编译缺平台 include；补齐后，首次设备任务又因加载时未恢复相同 include 配置
触发重新编译失败（`task_20261011_140015_292719532146`，尚未执行设备算子）。
修正实验驱动的编译/加载一致性后才得到上表。所有设备任务均已结束，详见 [任务记录](tasks.json)。

## 当前结论与下一步

无交接开销仍未清零：最近两轮核内候选比普通版多 0.07–0.11 μs。
已降低控制字段追踪成本；没有证据将剩余成本主要归于间接回调，也未发现/确认 CSA Scalar-bound task。
不能用 CSA 上轮均值改善替代本项验收，也不将当前差距认定为用户已经接受的代价。

下一步先审查能否通过内部调用约定直接传递 executor 已知的交接状态，避免 Wait 再次访存；
继续拆开尾部的后继探测与原 PIPE_ALL 兜底。任何候选都须维持原调度、ACK 和 early-resolve 语义，
并同时检查无后继短路径与真实交接正确性。若需要接受新的运行代价，按用户第 5 条先讨论。

## 复现入口

私有根目录：`.worktrees/scalar-overlap-demo-20261009`。
诊断源码在 PyPTO `tests/st/runtime/scheduling/task_boundary_overhead_analysis.py`，
`PYPTO_BOUNDARY_DIAG_BLOCKS=1/48` 在编译和运行时必须一致；用 `--variants` 指定需要的对照。
先按对应版本构建私有 SDK 和 torch 适配库，再使用 `--compile --compiled <目录>` 离线编译。
`--profile --batches 1` 采核内窗口；关闭 profiler、`--batches 1 32` 比较完整调用。
归档 shell 脚本放回私有根的 `artifacts/` 后，经预检由 `task-submit --device auto --device-num 1` 执行。
运行 `python analyze.py` 可从原始记录复算 [汇总](analysis.json)。
补丁基点为 Simpler `a9edc8455`、PyPTO `d8e8e5935`；本轮没有 PTOAS 改动。
