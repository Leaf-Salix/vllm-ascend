# CSA 单 SPMD：当前目标与验收约束

用户于 2026-10-17 明确确认：**降低至少 30%**，以 `SPMD ≤ 动态分 task PTO × 0.70` 逐档验收。
本目标替换此前 128K/B16 <700 μs 单点门槛。原始目标文件保留在 GOAL_USER_ORIGINAL_20261017.txt。

目标：将 CSA 的所有 incore task 融合为一个完整的 SPMD 算子，支持动态输入形状和按工作量分档，并使每个性能验收档位相较原动态分 task PTO 的完整耗时降低至少 30%。

一、动态形状与分档
1. 根据 CSA 自身的 batch_size、历史 seqlen、本轮 query 数及总 token 数，选择合适的分块、分核、历史切分、流水和合并策略。
2. 分档应覆盖输入区间，不能把几个测试点写成支持白名单。HC_pre 仅作为设计思路参考，不照搬其阈值或专用分支。
3. 档内继续根据实际 device metadata 计算有效范围、地址、循环次数和尾块，不能固化测试输入。
4. 允许不同形状分别 JIT 编译、缓存不同二进制，不要求一份二进制覆盖多个 batch。
5. 明确支持范围和策略边界；精确形状特化必须有 CSA 自身的依据及实测收益。
6. 后续开发和优化直接作用于正式动态 CSA 的源码与生成入口，不再围绕冻结的 B16/S6 entry_jit 或其他单点生成产物做优化。按 shape 分别 JIT 是允许的编译实现方式，不能代替按输入区间工作的动态算法；B16 只作为验证点。已有静态实现和结果保留。
7. 静态 shape 版本只能在 tests/pypto_test 中作为历史参考。ops/pypto 只能保留目标态动态 shape 源码：入口保留 pl.dynamic，使用实际 shape 与 device metadata 计算有效范围、分核与循环；可以参考 hc_pre.py 按工作量区间分档，但不允许把完整形状实值化、静态展开的版本包装成正式动态算子。
8. 2026-10-17 用户明确允许增加策略档位，只要对性能综合有利。七个验收点不限制内部策略数量；新增分支应依据工作量区间和完整 CSA 的实测收益，验证代表值与边界，不能把验收样例写成支持白名单。
9. 2026-10-17 晚用户进一步明确：KV cache历史长度与batch_size是主要分档维度；本轮输入长度偏静态，当前优先Dspark=5对应的S=6，同时必须考虑置信度变化下的S=5。S5/S6可以按实测选择分别特化或共用动态策略。此许可只针对本轮query长度的策略，不撤销T/B、KV长度和device metadata的动态处理要求；不能用token//固定S替代请求边界，也不能把所有请求强制视为相同有效长度。
10. 性能优化继续参考历史静态SPMD以及独立 `vllm_ascend/ops/pypto/hc_pre.py` 的工作。对照分核、依赖、流水、阶段融合、中间数据复用及工作量分档；迁移到正式动态源码后独立验证完整CSA收益，不能直接套用冻结调度表、输入实值或HC_pre阈值。

二、性能目标
逐档满足：单 SPMD 完整耗时 ≤ 同轮原动态分 task PTO 完整耗时 × 0.70

起始回归规格均为每请求本轮 query 数 S=6：
- 历史 128K：B4、B8、B16、B24、B28。
- 历史 8K：B16、B32。

2026-10-17 按用户要求移除 8K/B24、增加 128K/B28，仍为七个验收点。旧 8K/B24 的代码、数据与记录仅作为历史证据保留；新增 128K/B28 需要独立建立同轮基线与动态单 SPMD 的验证证据。

七个规格必须各自达标，不能用平均收益替代。它们只是回归点；最终各策略区间还须选择代表值和边界值验证正确性及性能，不能只优化孤立样例。

三、比较与验收口径
1. 使用正式权重 /data/model/DeepSeek-V4-Flash-0731-w8a8。
2. 基线为原动态分 task PTO，比较完整 CSA 算子；不以 Native、子阶段或整网其他开销替代。
3. 计时采用完整 L1 incore 最早开始至最晚结束，包含内部等待和阶段间空隙，排除外围 AICPU/orchestrator 首尾开销。
4. 两侧使用相同输入、权重、设备配置和测量条件，以同轮多次采样的中位数计算收益。历史数据用于参考，最终达标需复核。
5. CPU 成本模型、插桩计时和单次最小值不能作为性能达标证据。

四、实施与交付
先保证功能，再验证精度，最后优化性能。遵守既有精度要求，检查输出、Top-K、cache/state、动态 metadata、图重放和核间同步正确性，不通过跳过计算或放宽阈值获得性能收益。
保留原静态版本及既有结果，持续记录实现、尝试、失败原因、测试证据和逐档对比。完成可维护的区间策略入口，明确尚未支持或尚未验证的范围。只有动态形状要求及所有性能验收档位均完成，才将目标标记为完成。
按用户要求做阶段性详细中文commit，保存中间实现、采用/未采用的优化、失败原因和证据路径；不等最终性能达标才提交。大快照与编译二进制保留本地，Git记录可复现脚本、过程文档、报告及路径清单，不做额外hash校验。

完整形状实值化生成链已从 ops/pypto 迁回 static_shape_archive_20261017。当前正式动态单 SPMD 的 HC 行依赖、Attention 页有效列修正及输出组流水版本已完成七档固定 S6 的完整执行、精确对照与同轮性能测量。128K/B16、8K/B32 另通过同址图历史/位置/页表/compact metadata 变化，以及满档→B-1→1→满档的整请求 padding 重放。mixed-query、空 rank、其他动态边界、请求生命周期、prefix 共享和连续状态演进仍未完成。七档性能均未达到降低 30% 的目标。历史静态结果不能作为动态版本的验收证据；最新结果与版本见 ops/pypto/DSV4_CSA_SPMD_OPTIMIZATION_LOG.md。

五、源码可读性
新的动态 shape 代码必须有完整、完善的中文注释。每个算子文件在最开头提供整体思路总览，说明输入输出与布局、动态维度及有效边界、分档依据、阶段数据流、AIC/AIV 分工、同步关系和工作区用途，并给出与下方函数对应的阅读顺序。关键分核、pl.range、pl.pipeline、pl.spmd、pl.split_aiv、notify/wait、缓存发布与尾块处理必须解释设计原因及正确性约束。按阶段拆分职责清楚的函数，避免不可阅读的巨型生成体；未支持或未验证之处如实标注，不以注释代替验证。
