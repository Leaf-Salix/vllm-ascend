# 128K单行块区间的O_A N192分块候选

目标是减少O_A的非满核尾轮，而非重复已有的K128双缓冲。现有128K/B16
使用一个M128行块、每组8个N128列块，共64项，24个AIC需要三轮；候选每组
改为5个N192和末64列，共48项，每核两项。较大N的片上资源/搬运成本也可能
抵消收益，因此任务数减少不能作为性能结论。

策略条件为长历史、64≤T≤128，覆盖单M128行块的区间；实际T、B、请求边界、
地址和有效行仍为动态。不针对B16/S6点名，不扩到多M行块。CPU没有提供样例
shape，58个符号轴保留。每列原先16次K256的FP32累加顺序保持，只改N分块。
末N块由权重Tensor slice的valid_shape裁成64列，输出assemble也保留有效列。

AIC组发布、AIV量化等待和关闭组流水分支都使用ceil(1024/N)的任务数。
没有只改数学helper而漏改owner集合。分组量化、INT8尾行填零、O_B、HCpost
和所有前置阶段不变。与32KiB Attention候选分开验证，不叠加未采用改动。

正式37份源码。独立完整CPU编译已通过、一个MIX；运行时的尾列、精度、图、
保护区和完整L1仍需真机验证，不把CPU通过预记为功能或性能通过。
先只提交128K/B16，正式权重、同进程三方五窗，沿用全部冻结精确门槛。

检查；这是本候选使用切片的错误假设，不据此直接归为组件bug。
