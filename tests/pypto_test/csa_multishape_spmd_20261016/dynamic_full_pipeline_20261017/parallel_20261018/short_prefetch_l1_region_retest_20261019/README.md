## 历史上沿否定全短G2启用，补检已有排序资源分界

H32760/B16已全检查通过，原多task771.80、参考728.84、候选738.50μs，
中位回退1.325%。因此不把8K三点正结果扩大成全短G2默认开启。

源码的非balanced路径先算steps=ceil(visible/768)，半叶跨度为
min(steps*384,4096)，随后indexer_topk_half_leaf在valid<=2048与
更大范围采用不同归并算法。使用Host已有max_seq_len//4作为visible
保守上界，可得到一个有资源依据的候选分界：steps*384<=2048，即
steps<=5（最多3840压缩行）。它是待实测启发式，不是对退步原因的因果证明；
不应只因代码有分界就宣称预取一定适合这一侧。

补验H15352（上界3839，最多5步/半叶1920）与H15360（上界3841，
最多6步/半叶2304）两侧，B16/S6、同v3、各五窗和全部冻结门槛。
两侧都强制prefetch=1用于判断，正式策略仍未改。若资源边界内也无收益，
不继续凭孤立测点构造复杂适配。
