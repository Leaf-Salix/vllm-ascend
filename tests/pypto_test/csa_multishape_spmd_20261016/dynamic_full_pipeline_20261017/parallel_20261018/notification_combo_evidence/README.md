# 两类通知优化的组合：三档完整通过，效果不一致，不采用组合

候选由两个独立改动构成：已采用的HC四阶段有效消费者guard，加上删除
SCORE_CUBE/ATTN_CUBE两个无人等待的AIC阶段发布。只涉及两份schedule，
不包含Q_B双缓冲或其它数学改动。实际T/B、device metadata、72核代际、
组内FFTS/ACK排空和原消费者数据获取均保留。

同进程参照是`../hc_active_notifications_evidence/source_candidate/`，
即已采用HC guard的版本；不是d56裸版。不能把两个独立作业的收益相加。
未另做冗余CPU轮次，三个队列任务中各自完成完整动态编译、设备检查和
三方交替五窗L1。权重为正式W8A8，每请求S6；所有比较排除外部调度首尾，
保留内部等待和空隙，不测Native性能。

| 场景 | 原task μs | 已采用HC μs | 组合 μs | 相对HC耗时降低 |
| --- | ---: | ---: | ---: | ---: |
| 128K/B4 | 517.00 | 557.90 | 528.62 | 5.248% |
| 128K/B16 | 863.08 | 868.32 | 868.24 | 0.009% |
| 8K/B32 | 988.26 | 990.44 | 996.62 | -0.624% |

B4有4/5个配对改善；B16只有3/5个，0.08μs中位数差不作为可用收益；
短B32有4/5个配对回退。以上是三个独立作业内的对照，不横跨任务相减。
本轮不将组合设为默认，也不按三个样例建立B4专用白名单。正式源码保持
仅HC四处guard，两个AIC发布仍保留。Q_B负结果也保持隔离。

三个任务均exit0，原完整输出/Top-K/score/cache-state、A→B→A、图及
动态历史/页表、保护区、72核代际检查通过。只读原signal快照额外确认
HC发布集合、未发布槽保持，以及两个AIC被删阶段全槽为0。该读回没有
新增设备执行，不替代其它正确性门槛，也不构成Native/token验收。
三档相对原task仍慢，30%目标没有达标。
