# 原query-major布局的WS Acc列池：减少FIX写回指令

参考当前289cc072，只修改动态Indexer的AIC叶内WS结果存储。保留QK
M384/N64/K128、FP16缩放/ReLU、完整K384归约、当前Key预取、G6分叶和
两AIV Top-K。没有更改GM transfer布局或增加转置，不是旧key-major候选。

每份WS结果仍为16×64 FP32，直接写到16×512 Acc父池的八个列子窗。
八份完成后一次FIX写512列，每1024候选由16次TSTORE降为2次；不将结果
再搬运到Acc，不增加TINSERT。理论QK96KiB+WS池32KiB恰好128KiB，必须
核对真实分配与子窗别名；不能放宽硬件容量或删除FIX读完前禁止覆盖的依赖。
首半写回在生成WS第7片后，末半在第15片后，整步READY及双槽ACK不变。

旧score_transposed_layout_evidence的池沿key-major[512,16]和AIV转置，
整层曾回退约24%；本候选沿原[6,1024]接口，因而不能把旧负例当作本版
已经验证，也不能忽略旧版减少写回却没收益的教训。是否有效以当前同轮
完整L1决定，不以写回次数或源码容量推算。

仅既有G6/N64/1024/balanced资源组合进入；T/B、页表、位置、leaf与循环
仍为device动态，其它组合回退原路径。修改先在ops动态源码中完成，冻结
source_candidate后恢复当前正式源。无静态entry、无Host回读、无新GM工作区。
