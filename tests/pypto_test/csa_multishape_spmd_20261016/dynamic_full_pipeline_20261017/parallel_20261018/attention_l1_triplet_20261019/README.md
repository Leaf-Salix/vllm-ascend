# 2026-10-19：Attention三份独立L1槽与动态三拍环

## 假设与修改

现有Attention已将KV只搬入L1一次，QK与滞后两拍的PV共享同一数据。
原实现把三个槽放在一个384×512 Mat对象里，运行时子视图选择槽位。
这种表示可能使编译器保守地约束整块L1的复用；本轮改为三个128×512对象，
只展开固定的三个环相位，让每一拍的生产者和消费者更容易被分别追踪。

没有固化B/T/历史。外层轮数仍由实际T计算，query、mask、地址及尾部排空
保持动态。3只是已有硬件流水环深度。AIV helper与参考源码逐字相同；QK/PV
数学顺序、N128、GM ring、FFTS事件及正式GM等待/退避均不变。

三份KV共384KiB，Query64KiB、Probability16KiB，总Mat464KiB。
生成物已核对独立地址，且不存在不支持的Mat→Mat TMOV。
这不保证已产生预期重叠，是否有收益以真机完整CSA L1为准。

## 复现与产物

CPU脚本切换工作目录，所有传入路径应使用绝对路径。真机通过
`task-submit --device auto --max-time 1800`运行注册表中的完整命令。
参考、候选和原多task同进程同根交替采样，排除外围AICPU/orchestrator，
包括算子内部全部等待和阶段空隙。原始构建/泳道图仅本地保存，不计算hash。

## 真机结论：不采用

| 场景 | 多task μs | 当前单SPMD μs | L1三槽 μs | 候选较当前耗时降低 |
|---|---:|---:|---:|---:|
| 128K/B16/S6 | 875.40 | 824.52 | 827.40 | -0.349% |
| 8K/B32/S6 | 971.68 | 943.06 | 945.50 | -0.259% |

两档均5窗中位，全部窗口与门槛在`ALL_RESULTS.json`及任务原始result。
仅槽位表达独立，没有测出收益，不扩大七档，也不把更多静态事件直接解释成
实际同步开销。正式目录随后恢复参考，再进行独立PV按head整行写回候选；
本候选和参考完整保留，未来若上下文改变且有依据，可以复评。
