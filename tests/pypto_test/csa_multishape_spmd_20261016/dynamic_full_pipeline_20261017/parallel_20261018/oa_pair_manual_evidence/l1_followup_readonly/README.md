# O_A pair 四档既有 L1 只读分析（2026-10-18）

结论：不能从这批 L1 直接定位融合体内部 OA、quant、OB 分别节省多少。四个任务均关闭 `phase_clock`，候选和同轮参考每核只记录一次完整 `cube_schedule_spmd` / `vector_schedule_spmd` 起止。现有证据能把改善或退步约束到整核结束端点：T24 和短历史 T96 的改善在 AIC 结束时已经出现；长历史 T96 的 AIC 结束反而更晚，AIV 尾差略缩短仍不足补偿。不要用原分 task 的阶段时间替代融合体内部阶段时间。

## 4. 唯一建议：验证既有“小 T 单量化块 / O_B M32”资源域

这是可验证的下一步假说，**不是采用建议**。候选及参考源码位于相邻 `oa_pair_full_candidate_20261018/source_candidate` 与 `source_reference`，均继续冻结。

已有真实边界：

- `policy.py:100` 已按实际 T 选择 `OB_ROWS = 32 if T<=32 else 96 if T<=96 else 128`；`:108` OA_COLS128 的范围仍为 T≤96。
- `vector_schedule.py:927–949`：`R=ceil(T/32)`，量化行块 owner 为 `(g*R+r)%48`。T1..32 每组一个 owner（g），T33..64 每组两个，T65..96 每组三个。
- `cube_schedule.py:425–440`：OB 等本组所有 R 个量化 owner；原量化末块同时负责填到 OB_ROWS 倍数的 INT8 尾零。T1..32 是一组一次发布和 M32 消费；跨 T32 后同时出现多量化 owner 与 M96 消费。
- `output_projection_a_stages.py:206–250`：量化任务内部仍为每 8 行流水。OA 本身的实际 valid T 保持动态，整个 T1..96 区间都是一个 M128 数学 tile，8 组与 64 个 N128 输出不变。

pair 把 64 次各列块的逻辑 A 读取变为 24 次共享 pair 加 16 次 single，共 40 次；按有效行计算，T24 为逻辑少读 4.5 MiB，T96 为少读 18 MiB。权重逻辑总量同为 64 MiB，64 个独立输出的 K128 FP32 累加链不减少。不能把逻辑字节换算为完整时间，也不能从它单独解释为什么 T24 比 T96 更有利。

原每组八个 OA owner 变为三 pair + 两 single 的五个；量化每个 owner 都等待这五核。T≤96 时总量化任务只有 8R≤24，原本就分到互不重复的 AIV，没有“跨 T32 必然发生量化 worker 复用”的机制。新映射跨组尾波及组就绪时间的影响仍需观测。因此单量化块和 M32 给出了**非白名单的工作量区间依据**，但不足证明性能根因或全区间有效。

可以考虑 H131072/B5/S6 的 T30 作为下一次独立代表：它与已测 T24 处在相同单量化块/M32资源域，且保留既有 G6、16<T<32 的 QA 策略。当前 T24 的强收益及四窗中的长 T96 退步使这一次验证有价值；仅通过 T30 仍不能声称 T1..32、G2、mixed Q 全域都达标，也不能直接开短历史 T96 的点状例外。本次没有提交该任务。

历史排重只读范围：主 `DSV4_CSA_SPMD_OPTIMIZATION_LOG.md` 第 14700 行附近旧 oa_pair_source_v1、第 17010 行之后本轮 OA/OB 历史，`ATTEMPTS.md`，旧 oa_pair_source_v1 文档，以及本轮 pair 生命周期/完整接线文档。没有发现已经实测的独立“单量化块/M32 OA pair”策略。没有重提已否决的 OB→HCpost row/group streaming、OA 重复读取复用、全局阶段后移或 HC 通知删除。
