# PV N256 同轮生成物只读审计

结论：**没有找到短 B32 独有的分配改变或新增同步边，现有证据不能支持 T=144 作为启用边界。** N256 的确改变了 PV 的面板与存储粒度；这些改变在长 B16、短 B32 完全相同。本次未编译、未上卡、未改源码，只新写本目录两份文本。

同轮完整 L1：长 B16 为 881.40→873.04μs（降低 0.948%，5/5 更快）；短 B32 为 998.02→1017.26μs（慢 1.928%，5/5 更慢），两档完整精度 PASS。原始五窗及结果路径保存在 [evidence.json](./evidence.json)。长 B4 的结果由主会话收取，不在此次生成物检查范围。

## 实际物理资源

以下变化在两档都相同，地址/大小单位为字节。QK 的两个 Left/Right 槽包括编译器生成的匿名第二槽。

| 对象 | N128 | N256 |
| --- | --- | --- |
| QK Acc，64×128 FP32 | 地址 0，32768 | 相同 |
| QK Left，64×128 BF16 | 0、16384，各 16384 | 相同 |
| QK Right，128×128 BF16 | 0、32768，各 32768 | 相同 |
| PV 两份 Acc | 0、32768，各 32768 | 0、65536，各 65536 |
| PV Right | 所有面板复用地址 0，32768 | 所有面板复用地址 0，65536 |
| L1 Query/KV 三槽/Probability | 0/65536/458752，大小 65536/393216/16384 | 相同 |

**QK 与 PV 第一个 Acc 在 N128 时已经同址 0。** N256 没有新引入这项别名。PV Right 两版均为同址单槽，不能把 N256 描述成“从双缓冲降成单缓冲”。

完整 PTO 分配列表只出现一段差异：PV Right/Acc 的 11 条分配/别名记录变为 5 条。Attention 外长档 2178 条、短档 2020 条有序分配记录完全一致；全部 AIV 分配也一致。两档两版的全函数地址上界都为 Acc 131072、Left/Right 各 65536、L1 475136、AIV UB 163872。这里是地址上界，**不是并发活跃量或性能证明**。

## 实际事件链

两档同一 N 的 Attention `wait_flag/set_flag/pipe_barrier` 有序列表相同。检查的 PTOAS Attention C++ 范围逐字包含在实际 AIC wrapper 中。

- 两版都在 QK 的 FIX store 后设置并等待 `FIX→M EVENT_ID1`，再进入 PV，保护同址 Acc。
- 两版都在 tick 尾部（PV 最后一次 store/FFTS 发射之后）设置 `FIX→M EVENT_ID0`，下一 tick 入口等待该事件。N256 没有新加跨 tick FIX drain；N128 也不能越过前拍末尾 FIX 链直接运行下一拍 QK。
- PV Right 的后一面板 `TEXTRACT` 两版都先等前一 MMA 的 `M→MTE1 EVENT_ID1`。N128 是四个 32KB Right 搬运与四个 32KB Acc store，N256 是两个 64KB 搬运与两个 64KB store，总数据量不变。两版都先发射第二个 MMA，再发射第一份 Acc store。
- N128 为复用两份 Acc，在第三、第四面板 MMA 前各有一对 `FIX→M EVENT_ID1`；N256 两个面板各用一份 Acc，这两对消失。QK/末次 PV FFTS 的位置和粒度保持不变。

因而可验证差异是 **PV 面板更宽、搬运/MMA/store 发射次数减半、面板内 Acc 复用等待减少**，并非短档新增屏障。更宽面板下各流水完成时间及供数交互没有被本次静态检查测量；不能据此确认回退来自早 KV、资源压力、DMA 队列或某一个等待。
