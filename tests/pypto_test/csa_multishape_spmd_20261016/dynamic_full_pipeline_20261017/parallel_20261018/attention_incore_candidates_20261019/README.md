# 2026-10-19：从全72核流水验证Attention候选

## 本轮原则与基线

使用已经采集的完整72核incore流水提出候选，以同轮真机完整CSA L1及冻结
精度、状态、图重放门槛决定是否保留。用户明确：不为迁就模拟器修改真机
等待实现；旧负例只代表旧上下文，有理论依据可以在当前版本重新验证。

基线为当前正式动态源码，生产行为对应f222a917，留在`source_reference/`。
正式W8A8第4层。所有候选保留动态T/B/device metadata，不按B16固化算法。
没有变更get_sys_cnt、退避、GM点对点信号或FFTS协议。

## 候选1：当前版本重验PV N256

相较此前d253，协同前段、前置几何、细化Attention依赖和本地mi/li已改变
供数及工作区布局，因此重新验证原N256分块。候选只把四个N128 PV块改为
两个N256，K128及每个输出的归约次序保持。保存在`source_pv_n256/`。

首次CPU启动误用相对路径，runner切换至仓库根目录后找不到controls文件，
尚未编译；修正为绝对路径后`cpu_pv_n256_v2`完整PASS，58个动态轴、单MIX。
所有日志保留。生成物确认两份Acc分别0/65536，各64KiB，未增加AIV计算。

同进程三方交替五窗，单位μs：

| 场景 | 原多task | 当前单SPMD | N256候选 | 候选较当前更快的窗口 |
|---|---:|---:|---:|---:|
| 128K/B16/S6 | 874.08 | 838.32 | 847.26 | 0/5 |
| 8K/B32/S6 | 974.34 | 942.14 | 936.16 | 4/5 |

两档完整数值、Top-K/score、cache/state、保护区、代际和图重放检查通过。
长B16变慢、短B32改善，与旧版对应点的趋势相反；印证需要结合当前上下文
评估旧方案。暂不全局采用，也不据一个短档建立策略白名单。
结果与所有原始窗口见`PV_N256_RESULTS.json`及`DEVICE_SUBMISSIONS.json`。

## 候选2：QK/PV显式使用三个L0C窗口

流水与生成物显示：原QK score和第一份PV Acc同址0，QK的FIX写回之后
出现FIX→M等待，才进入PV。此候选将三份32KiB Acc放进同一
96KiB池的三个列窗口。QK继续按K128顺序，PV保留四个N128及原交替写回。
源码快照`source_acc_isolated/`；CPU完整PASS，实址为0/32768/65536。

仅改变算子后等待仍存在，继续定位PTOAS：`getPtoSubViewBaseAddresses`
对非NoneBox布局回退到整个父池，使这三个已知不相交的窗口仍被判为冲突。
最小IR在0.66和0.67均复现；完全相同的数学与地址改用两个独立alloc后，
额外FIX→M消失。提交上游[PTOAS #1623](https://github.com/hw-native-sys/PTOAS/issues/1623)，
附最小IR、不同版本结果、修改建议和本地patch，没有PR或标签。

独立PTOAS worktree中仅新增窄范围的连续Acc列窗口分析，保守回退仍保留。
7个CPU依赖例及仓内FileCheck通过；完整动态CSA生成物中，QK写回到PV计算
的额外wait已经消失，保护下次复用的事件仍保留。原参考完整生成物的4809
条同步调用，归一化SSA名称后顺序相同；不宣称整个C++或机器指令逐字一致。

PTOAS修改位于`.worktrees/ptoas-csa-parallel-copy-20261018`，继承其已有
并行赋值修复，未修改共享安装；新增translator实现、一个回归用例及说明。
首次按LLVM构建目录查找FileCheck失败，实际用`/usr/bin/FileCheck`完成，
没有把工具路径失败报告成编译器问题。

真机结果已收齐，见下表。该候选未整体采用，正式目录随后恢复参考行为，
再开始下一轮L1三槽候选；本目录保留全部完整源码快照。

## 八个真机任务的完整结果与取舍

八个任务均completed、exit=0；输出、Top-K/score、全部cache/state及保护区、

没有使用模拟器128次读取上限。每行是在同进程、同输入根地址的三方五窗，
跨行的reference波动不能拿来充当候选收益。

不等于保证整个CSA加速；当前实测混合结果已保留。
