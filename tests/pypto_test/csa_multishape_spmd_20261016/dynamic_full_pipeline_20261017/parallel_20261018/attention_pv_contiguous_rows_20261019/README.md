# 2026-10-19：PV按head半区完整行写回

## 从当前流水提出的假设

诊断图定位到Attention QK/PV的FIX写出。此前仅加大N或拆Acc池没有稳定
整体收益。本轮改变PV的写回几何：四个64head×128列的跨行片段，改为两个
32head×512列完整行片段，两个64KiB连续写回。GM张量布局、总写出字节数、
AIV每lane消费32head的协议均保持。

A3的L0B只有64KiB，无法容纳完整128×512 BF16。因此选择K64，两个K片
均按先head0..31、再head32..63计算，每个K片的Right只搬一次，两head半区
共同使用。两种写法各为4个MMA，Right合计128KiB、Left合计16KiB；没有把
KV重复搬入L1，也没有把L0B上限放宽。实际机器指令及重叠仍需生成物核对。
两份32×512 FP32 Acc放在同一128KiB池的不同列窗口，局部PTOAS的连续
Acc范围分析保留不相交事实。最后一个K片先提交第一半FIX，再计算第二半。
完成两半后才沿原FFTS协议发一次PV_READY，AIV源码逐字不变。

T/B及device metadata仍动态，仅模型固定的head/K维度分块变化；不是某个
batch的完整展开。K仍升序，但K128拆成两次K64可能改变硬件累计舍入，
必须通过冻结的精确输出/Top-K/score/cache/state门槛，不能以数学等价代替。
