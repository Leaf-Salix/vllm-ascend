# 保持QK，按独立query拆分WS Right：完整正确，单点小收益暂不采用

2026-10-18。目标是较大的Score搬运流水，不修改AIV归并或全CSA阶段依赖。
参考冻结为前置几何首版，候选只改 `indexer_score_stages.py`；两侧均不
包含另一实验的几何排程改动。本结果不能直接当作之后组合版本的验收。

## 与历史尝试的区别

旧M192/N128同时拆QK、扩大N并减少Key的L0预取；旧N80/K128改变N并把WS
归约拆成多个K片。本候选保留QK M384/N64/K128、两份8KiB Key、原FP16
FIX/ReLU边界、1024交接及AIV。只在既有G6/N64/balanced区间，把相互独立
的六条query分成两组三条，WS分别读取K192。单query的64个有效head项仍
在一次MMA内；系数生产者原样生成对角矩阵，舍弃的其它query列系数为零。
这只证明数学结构，不能据此提前宣称硬件FP32累计或Top-K精确一致。

两个WS Right各24KiB，配合两个8KiB Key正好64KiB。两份系数Left各6KiB，
query Left48KiB，合计60KiB。GM系数load有效行为3，不能用物理M16跨读
最后一组的GM。每panel两次三行写回，最后统一发原SCORE_READY，不改ACK。

- v1：直接跨两个if引用分支局部Tile，ConvertToSSA拒绝作用域越界。
- v2：改为外层占位/分支赋值，但初始Tile的valid_shape与M3赋值不一致，被
  类型检查拒绝。没有改编译器或绕过范围/类型校验。
- v3：占位同样声明M3有效域，完整动态编译通过。实际Right第一半0/24KiB、
  第二半24KiB/24KiB，Key后续48KiB与56KiB各8KiB；Left系数48KiB、54KiB。
  C++两半有各自MTE1→M事件，QK/第一半WS不等待第二半对应事件。

越过64KiB。AIV函数AST完全相同，仍58动态轴、130根和一个MIX。这里只说明
表达、容量及生成顺序，没有证明实际重叠时长、精度或完整L1收益。
