# 区间源码编译过程

v1 开/关两份完整动态编译均通过58轴、单MIX。检查发现关闭路径虽然没有
证明与快读，但仍共用候选的FP16零/fillpad初始化；为完全保留旧路径，
v2在constexpr关闭时恢复原INT16零初始化，不以等价数学替代关闭语义。
v1完整源码和生成物保留；v2仍需两条路径完整CPU验证。

v2开/关编译都在类型推断失败：同一single_scale_bytes跨constexpr分支
具有PadValue.zero/Null两种Tile类型，不能假定前端先裁分支。
v3统一为原INT16零/Null目标，快路通过完整assemble写入，避免跨分支改变
Tile类型；关闭路径完全是原初始化。该操作可能产生额外Vector复制，需
检查生成物并真机判断，不以源码行数或CPU通过宣称无开销。依赖未修改。

v3开启路径被后端拒绝：tile.assemble两侧pad必须一致，不能用assemble
清除padding元信息。保留完整源码/错误后，恢复已完成开关双CPU验证的v1，
当前source_candidate与cpu_on/off_v1源码逐文件一致，不重复已通过编译。

选择保留v1的等价FP16全零初始化。关闭时没有证明尾区、页扫描、快路读取，
仍逐页gather；不宣称C++逐字等同旧INT16初始化。其真机性能由B8关闭
对照检查，不能据源码看起来等价直接记收益。未修改任何依赖或新报组件bug。
