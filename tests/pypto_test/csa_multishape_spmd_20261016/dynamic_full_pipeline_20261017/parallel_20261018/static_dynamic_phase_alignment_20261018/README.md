## 已确认的性能差距

此前未插桩、同进程五窗完整 L1 的 128K/B16/S6 对照为：

| 版本 | 中位耗时 / μs |
|---|---:|
| 原 PTO 多 task | 869.78 |
| 正式动态单 SPMD | 889.40 |
| 历史静态单 SPMD | 792.78 |

来源：`../score_attention_interleave_candidate/static_same_process_h131072_b16_v1/result.json`
的 `l1.statistics_us`。该轮 `phase_clock=false`，五窗全部保留。
动态比静态慢96.62 μs，即12.19%。静态比原多task只降低8.85%；即使追平静态，
仍未完成降低30%的目标。该档按此轮基线需达到608.846 μs。

## 此次如何对齐

- 正式动态33模块冻结在 `source_dynamic/`，来自 `aa7f1df8` 时的正式实现。
- 静态版使用已验证的 `b16_cached_row_deps_v1` 和原选择策略，不重新生成另一份排程。
- 正式 W8A8 的第4层权重；128K/B16/S6；历史内容为原测试合成输入。
- 两侧同进程、共享原输入地址、A→B→A 三轮交替执行；原多task提供精确参考。
- 两侧仅在已有 TNOTIFY 周围增加相同的四字设备时钟写入，不改等待、FFTS、数学、
  业务 fence、信号发布或原缓存维护。没有增加参数和新的业务工作区。
- 动态时钟存于各 phase/核独占槽第16..19字；静态存于各核槽的
  `16+4*dispatch_seq` 处。静态最大序号22，末字107，未越过原128字隔离区。
- 每次发布的时钟字之外，继续检查原 padding、控制表和工作区保护。

输出、Top-K、score、cache/state、A→B→A、图重放和原有保护检查均通过。
`OFFLINE_HOOK_CHECK.json` 记录插入前后等待调用保持不变的离线审查。
`STATIC_ENDPOINT_COVERAGE.json` 逐阶段核对每核末成员是否真的发布，防止拿
部分核的结束冒充完整阶段结束。

## 新证据及解释边界

配对端点的三轮中位显示：动态 HC 归一化比静态早10.52 μs，QA早14.36 μs，
Indexer query RoPE早22.70 μs；到Score AIV完成，动态变为晚30.24 μs，
Top-K晚38.68 μs，Attention AIV晚74.46 μs，OB晚75.52 μs。
因此，这次诊断中差距主要在Score前后与Attention区间扩大，不能继续将主要
差距笼统归因于前置metadata、HC或动态shape本身。

两侧时钟记录数量为动态1619、静态794；相同的单次探针不等于相同的总扰动。
这些数字是相对最早BEGIN的完成端点，包含启动偏斜、计算、等待、搬运、缓存
维护和插桩。**不能将端点差当作未插桩96.62 μs的精确拆账。** 静态Attention
AIC和最终HC_post没有完整发布端点，此处不填造它们的时刻。

源码可直接确认的排程差异：

1. 动态 `cube_schedule.py:337` 先完成主压缩投影，再进入Indexer Score。
2. 动态 `vector_schedule.py:760` 起依次做主Query反量化、主压缩pool、state
   commit和cache输出，到829行才进入Score的AIV消费者。这些主Attention输入
   不是Score自身的直接输入；它们在当前统一阶段次序中排在Score前面。
3. Score AIC/AIV用两槽READY/ACK交接。AIC能提前发两槽，不代表其可在AIV未
   到达时一直推进。消费者入场顺序会反过来限制生产者。
4. 静态版按每核成员依赖推进，一些核先做Score，另一些核完成独立工作；它不是
   将当前动态源中的shape替换为常量而已。

这些是需要优先解决的整层结构差异，不代表把上述一段代码简单前移即可获得
固定收益。此前4辅助核方案已经出现生产者提前、消费者迟到并导致完整L1
回退；修正版仍无收益。Attention区间还须区分入场等待与核内流水，当前只有
完成端点，不能宣称已找到具体指令级根因。

近期区间分支裁剪未缩小长B16差距（正式886.36 / 候选887.94 μs）；Q_B双L0
候选回退4.71%；Score转置及Acc pool也未带来完整L1收益。这些失败说明减少
分支、局部搬运或写回次数不能代替整条依赖链验证。编译器修正有必要，但容量
通过、编译通过不等于性能提升。正式算法仍保持原实现，目标仍0/7。
