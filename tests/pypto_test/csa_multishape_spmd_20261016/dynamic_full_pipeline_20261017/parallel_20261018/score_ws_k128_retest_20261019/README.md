# 2026-10-19：当前动态G6 Score重验WS K128流水

## 依据及与旧实验的区别

现有72核模型中多处WS的384×64 FP16 L1→L0B搬运值得核对，但模型累计
时间不等于真机瓶颈或可省时间。本轮沿当前动态Score保持QK M384/N64/K128、
原FP16缩放/ReLU边界及一次最终WS写回，只把WS的K384拆成0/128/256三片。
两个16KiB Right与原两Key并存，Left复用原系数的三段4KiB别名。

旧N80静态版本也试过WS K128，但N、排程及编译器不同；另一个G6候选曾把
六query拆成两个M3/K192并分两次写回。本轮保持整个16行输出累计和一次写回，
不是重复称query拆分为新优化。当前几何/前段/依赖/UB统计也已经改变，
按用户要求可用当前真机重新验证，不将旧负例永久排除。

仅在既有query_group_size=6区间编译新路径；G2源码沿用原算法。本轮只验证
G6，不将源码分支未改冒充G2已完成新回归。T/B、每请求长度、页表、叶范围和
动态循环仍在device，三片K是策略/模型常量，不是冻结测试形状。
QK计算先提交，随后WS按K128流水，最后沿原位置把QK写到L1 FP16并交付WS。
AIV、Top-K、FFTS、业务缓存和GM等待完全沿用，未叠加Attention候选或GM优化。
