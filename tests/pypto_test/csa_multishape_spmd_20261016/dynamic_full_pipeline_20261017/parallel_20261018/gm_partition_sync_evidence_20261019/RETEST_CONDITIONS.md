# 历史候选的重新验证条件

用户最新要求：旧负例只描述旧版本和旧瓶颈，不是永久禁用名单。要有当前
数据流/编译变化的理论依据，真机同轮验证后再决定采用；不无差别重跑旧实验。

| 候选 | 旧/当前已有证据 | 重新验证的条件与优先级 |
|---|---|---|
| QK/PV独立Acc | 当前短B16/B32改善2%～2.6%，长B16回退1.6% | 若GM列分片修复获得真实收益，优先重验；原FIX barrier会限制写回重叠，消除后Acc分离可能产生不同效果 |
| PV N256 | 当前短B32小幅改善0.64%，长B16回退1.07% | 新编译器把N128的四个barrier移除后，重新核对大块写回与L0B单槽的取舍；不直接沿用旧符号或归因 |
| PV按head整行写回 | 当前短B32改善2.27%，长B16持平 | 先与修正后的原N128比较；它仍有相同行内列范围、不同动态行起点，当前窄GM列证明不会消除其全部barrier，原收益可能变化 |
| Score的L1→L0B搬运 | 旧load2D方案没有整体收益；当前模型中有多处重复384×64 FP16搬运 | 先收齐Attention修复结果；若Score成为更主要限制，再结合生成指令与设备证据重验，模型累计时间不能当收益上限 |

当前不把这些方案全部提交七档，也不改生产等待。每次只改变可识别的因素，
两个代表点通过后再按工作量区间与边界扩展，性能目标和精度门槛保持。

最新真机结果：全GM列修复长B16降低2.286%、短B32回退1.475%，两档全门槛
通过，故未全局启用。先隔离FIX与MTE3影响，再决定Acc组合重验；不能因为
长档改善就默认短档同样获益，也不能因此永久否定合法的同步消除。
