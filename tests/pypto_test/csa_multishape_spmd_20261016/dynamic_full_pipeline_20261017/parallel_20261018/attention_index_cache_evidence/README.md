# 动态 Attention 索引/页表 UB 缓存：完整通过但未取得性能收益

2026-10-18。静态/动态端点对齐显示Attention段落后幅度扩大。进一步核对实际
静态B16源码：其 `stage_30` 已将64个Top-K索引与页表载入UB，由Vector计算
物理行；正式动态版仍逐行从GM读取索引和页表。此轮在正式动态源码补齐同类
路径后做完整同轮消融，没有修改PyPTO/Simpler/PTOAS或共享安装。

## 实现与边界

- 新开关 `ATTENTION_INDEX_CACHE`，默认关闭。入口仍保留全部动态轴。
- 每块读取64个索引，页表预留2048个INT32即8KiB，实际只加载device描述符的
  有效列。Vector shift/gather/add得到页号和物理行，Scalar从UB取地址。
- 预算来自片上容量，不将B16/128K作为白名单。空页表、超过2048列、物理行
  超出INT32范围时继续原Scalar路径，不拒绝原本可处理的输入。
- Vector gather用夹紧到真实页表范围的列号；KV搬运仍用原始索引验证列界，
  单独验证物理页上下界。不能只验证移位后的物理行，否则坏页号可能回绕。
- KV逐行DMA次序、softmax/PV/归并/逆RoPE、各FFTS及阶段通知均保持。

`source_reference` 是修改前33模块；`source_candidate` 是实际被测33模块。
CPU和设备均从冻结候选加载。正式源码已移除本候选，后续协同前段候选没有
叠加此开关，不用失败路径污染下一轮的归因。
