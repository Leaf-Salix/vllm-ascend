# O_A行块轮换：优先128K/B24、B28

原O_A在T>128且使用N256时，每输出组有2个M行块×4个列块。执行槽按
logical%24分核，24恰是每组8项的3倍，导致同一批AIC反复拿到满128行块，
另一些核反复拿到短尾块。这里先修正可由源码直接确认的工作量偏斜。

只把组内物理行块从rb映射为(rb+group)%row_blocks，group、列块和执行槽
owner均不变。两行块时奇数组交换满块/尾块；更多行块仍为同一个循环置换，
单行块跳过，不依赖某个B/S测试点。每一输出块的tile、K累加、有效行、地址
边界和量化规则保持。原量化按组等待全部OA owner，因此组内置换不改变等待
集合；没有新增信号、GM搬运或Host metadata。

36个整数覆盖场景确认输出唯一覆盖、整组owner集合及总工作量保持。在N256下，
T144最忙核的行×列工作量98304→69632，T168为98304→75776。这是分配量，
不是周期模型或性能收益；不同大小tile开销、量化重叠和后续O_B仍须完整实测。
