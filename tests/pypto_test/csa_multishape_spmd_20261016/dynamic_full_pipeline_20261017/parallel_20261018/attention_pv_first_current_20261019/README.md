# Attention每tick先旧PV再当前QK

当前正式版阶段时钟显示短B32的Attention仍约250μs（other，含内部等待/搬运/插桩），
长B16约157～166μs。两侧相近不能确定瓶颈引擎，因此只提出明确的供数重排候选：
AIC原来先等待KV(t)再算QK(t)，随后才消费已就绪的P(t-2)；改为先PV(t-2)，
再进入QK(t)，让AIV准备当前KV时，AIC有机会先做旧块计算。

仅移动两个完整if子树；QK、PV数学AST逐节点相同，AIV整个函数AST相同。
保留原3份L1 KV、GM三槽、两拍lead、所有事件ID/次数和每类消息顺序。
PV(t-2)在QK(t)之前，两者L1槽不同；QK(t)重用的t-3槽已在前一tick被PV消费。
空mask两侧仍同时跳过事件及业务，qk_q只在每query第一块更新，PV不读它。

AIC等P(t-2)所需的AIV步骤不依赖QK(t)：对应softmax在AIV tick=t-1，
只等SCORE(t-2)；早KV路径最多先要求SCORE(t-2)，该QK在两拍前已发出。
这个有向关系是检查依据，不把源码分析当成真实硬件协议验证。

旧Score/Attention交错也用过PV先行，但同时把L1缩成2槽、改变驻留与wave，
整层负例不能隔离本改动。本候选不包含这些变更。概率未就绪时PV先行可能
阻碍QK，故不预判收益。CPU及设备未通过前不采用、不更新七档最佳。

候选从ops动态源码修改并冻结，已恢复正式参考；没有静态entry/Host回读、
依赖修改或门槛放宽。完整G6与G2资源组合编译后，分别对长B16、短B32做
原多task/当前单SPMD/候选三方五窗，保持原metadata/padding与图重放检查。

完整G6/G2 CPU均通过58符号维度、单MIX；384×512 L1池及其分支/回边别名
都为Mat65536，仍3槽。audit_fifo_order.py在原/候选顺序、两种AIV交接和
两query的全部1024个有效mask组合下检查4096个DAG，事件无环且三槽均先读
