# 静态 SPMD 新旧性能差异核对

日期：2026-10-20。用户要求查清静态参考列的变化；不恢复性能优化，不 push。

结论：静态数学和调度没有变化，旧、新都为 NZ2、cached100 等待和完整
72 核 L1 首尾口径。三个代表档直接重放历史与最新二进制，控制运行条件后，
只见到约 2～6 μs 的中位差，未重现旧表到新表的几十微秒变化。旧、新表
属于不同轮次、不同构建和不同运行前序，不能把其绝对差计作算法收益。
历史频率、L2 状态、温度及邻卡负载没有完整记录，不能事后唯一归因为降频、
缓存或编译器。以下把已排除项、实验证据及剩余边界分开记录。

## 1. 六档原始结果

单位 μs；变化为新值减旧值。两列多 task 必须取各自静态测量轮的配对基线，
不能误用五列表中与动态单 SPMD 配对的另一轮多 task 数值。

| 场景 | 旧静态 | 新静态 | 变化 | 旧同轮多 task | 新同轮多 task |
| --- | ---: | ---: | ---: | ---: | ---: |
| 128K/B4 | 541.92 | 467.58 | -74.34 | 582.82 | 502.64 |
| 128K/B8 | 641.56 | 597.02 | -44.54 | 679.84 | 634.64 |
| 128K/B16 | 781.94 | 778.94 | -3.00 | 880.06 | 871.04 |
| 128K/B24 | 1121.12 | 1095.70 | -25.42 | 1169.46 | 1122.52 |
| 8K/B16 | 621.96 | 640.82 | +18.86 | 680.02 | 684.28 |
| 8K/B32 | 905.72 | 931.66 | +25.94 | 972.72 | 981.26 |

B4 相对同轮多 task 的提升约 7.55%→7.50%；B8 约 5.97%→6.30%，变化很小。
因此 B4/B8 的绝对值大幅移动同时存在于基线，不能只解释为静态算子变快。
8K 的方向又不同，不能用一个统一比例修正所有档位。

128K/B28 没有已验收的静态实现，继续留空。此次未修复或测试该静态档。

旧表也不是统一日期：多数静态值取 10/16，B16 的 781.94 取 10/18
`projection_branch_evidence/h131072_b16_branch4_v1/result.json` 的静态角色。
B16 更早的 807.16 与后来独立迁移验证的 782.66 都是另外的实测，不能混为同轮。
本报告沿用用户看到的旧表 781.94，所有来源保存在 `ANALYSIS.json`。

## 2. 排除的几项原因

- 六档旧入口与 ops 静态归档的四个 Python 函数 AST 完全一致；
  workspace 内的 records、waits、临时区和偏移合同完全一致。
  归档只改变导入、说明和记录路径，未改数学、分核或依赖。
- 旧测试已有 `weight_nz_mode=2`；新测试另检查四张主要权重实际格式为29。
  不是 ND→NZ。
- 新旧全部原始窗口重新按 `(max(record[4])-min(record[3]))/50MHz`
  计算，均与报告一致，覆盖72个角色。单 SPMD 每窗72条记录且一个任务。
  50MHz 是时戳计数器频率，不是 Cube 工作频率。
- 静态旧测试本来就执行 AB/BA；新静态 runner 也是 AB/BA。
  此前修复的“两方轮转再反转相互抵消”属于动态对照 meter，
  不能用它解释这里的静态变化。
- 新旧均保留真实等待、cached100 退避、完整 CSA 输出/状态范围；
  没有采用模拟器跳过等待或扣掉内部空隙的计时。

另外核对72个角色的起跑时戳分散：B4旧/新中位仅9.06/7.68 μs，
B8为7.78/6.68 μs；最大单核自身起止区间则分别539.58→465.18、
636.14→595.16 μs。主要变化也存在于核内区间，不能解释为把外围AICPU
首尾误计入或仅仅核组起跑更整齐。它仍不能进一步区分历史缓存、
工作频率、信号轮询等运行条件；逐窗起跑分散和单核跨度已加入JSON。

工具链确实不同：多数旧静态使用 `pypto-csa-static-fixes-20261016`，
旧表 B16 使用 `pypto-csa-memory-reuse-20261018`，最新统一使用
`pypto-csa-repro-20261019` 和 `ptoas-csa-repro-20261019/build`。
生成的 C++ 也不同，包含负余数修正、Tile 分配和事件编号等 lowering 差异。
但“生成代码不同”本身不能证明 74 μs 来自编译器。

旧测试通常5次预热、20次 Event 重放后采3窗 L1，新静态为3次预热、5窗 L1；
卡号、前序进程和工作区地址也不同。最新五口径中，静态和动态分别与多 task
配对，分属同一卡的不同进程阶段，不能将静态/动态两列称为同进程直接 A/B。

## 3. 三档现成二进制的同卡实验

为识别二进制因素，只做 B4、B8、8K/B16；未重新跑七档。
每档在队列分配的同一卡、同进程，使用同一套正式 W8A8 权重、seed1024
输入、根 Tensor 地址和工作区。直接装载两个已有 `prebuilt`：

- 旧二进制来自产生旧表数据的历史构建目录。
- 新二进制来自本次五口径最新测量的静态构建目录。
- 两侧130项根 ABI 完全相同、Simpler revision 相同。
- 使用 PyPTO `load_prebuilt` 保留运行时原有校验，不调用编译器、不写原产物。
- 六次配对预热，六个 L1 窗口，AB/BA 各三次。复用同一逐代递增进度区。
- A→B→A、图重放、完整输出/Top-K/score/cache/state、保护区及32次实际
  调用的进度协议均检查通过；旧、新逐 bit 相同。
- 两侧未执行 Native 或已被其他会话修改的多 task 算子。

| 场景 | 同进程旧二进制 | 同进程新二进制 | 新中位净省 |
| --- | ---: | ---: | ---: |
| 128K/B4 | 489.85 | 483.83 | 6.02 |
| 128K/B8 | 609.02 | 604.94 | 4.08 |
| 8K/B16 | 628.65 | 626.32 | 2.33 |

三个任务均 completed/exit0：

| 场景 | 任务 |
| --- | --- |
| 128K/B4 | `task_20261020_133612_196771226801` |
| 128K/B8 | `task_20261020_133707_201353111471` |
| 8K/B16 | `task_20261020_133708_201448826177` |

这说明：

1. 同一旧 B4 二进制这次就能跑到489.85，而旧表是541.92；旧 B8 同样从641.56
   变成609.02。其变化不可能归于该二进制自身的算法更新。
2. 控制条件后，旧、新二进制未出现历史表中的74/45 μs差距；编译产物差异
   在本轮只有小幅中位影响，不能把跨轮差额全记为编译器收益。
3. 8K/B16 新二进制此次略快，旧表中的18.86 μs反向差不支持“迁移后必然回退”。
4. B24、8K/B32没有额外直接 A/B，不将前三档的量化结论机械外推到它们。
   六档共同的源码、口径及数据来源审计均完成。
5. 本实验也不能重建历史环境；没有给未记录的频率、L2命中和并发负载分配
   虚假的百分比。配对有小幅噪声，2～6 μs不作为新的优化采用结论。

## 4. 后续比较的使用方式

`../PERFORMANCE.json` 保留原始七档五口径结果，不把本诊断三档中位数混进去。
需要判断动态与静态的真实差距时，使用同一轮的直接配对；
历史绝对耗时只作参考，不通过跨轮相减宣称代码收益。

此后 Native 布局按现有 vllm-ascend 支持度处理：DeepSeek-V4 decode 的 QLI
明确传 TND，CSA 明确传 `layout_q="TND", layout_kv="PA_ND"`。
模型路径无现成 BSH/BSND 切换开关；按用户最新指示，不增加适配或另测 BSH。

## 5. 文件与复现

- `analyze.py`：离线重算原始时间戳、核对 AST/workspace 并生成 `ANALYSIS.json`。
- `prebuilt_pair.py` / `run_pair.sh`：二进制直接配对诊断，仅依赖已有本地产物。
- `artifacts.json`：每档旧、新产物路径。二进制本地保留，不提交。
- `results/<case>/pair_v1/result.json`：精度、环境、逐窗耗时及信号记录。
- `results/<case>/pair_v1/l1_*`：对应原始泳道与名称表。

离线复核：

```bash
python tests/pypto_test/csa_five_way_latest_20261020/static_history_audit/analyze.py
```

需要在新的输出目录复现某一档时：

```bash
task-submit --device auto --max-time 1200 \
  'bash tests/pypto_test/csa_five_way_latest_20261020/static_history_audit/run_pair.sh 131072 4 pair v2'
```

脚本拒绝覆盖旧结果，并验证队列追加的 `--device` 与分配卡一致。
