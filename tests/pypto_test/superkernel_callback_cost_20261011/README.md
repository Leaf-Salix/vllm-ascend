# 过程060：尾部回调诊断、内联与DMA前重查

本轮两个优化候选均未取得CSA收益，均未接入默认。运行时、编译器生产代码和公共算子保持不变；
仅提交可复现的私有测试驱动。空回调只用于诊断，不作为完整后到观察的替代方案。

## 第一轮：空回调诊断与内联

原后到路径会重新进入当前kernel的私有tag入口，再调用独立`noinline`尾部函数。
空回调保留入口和独立函数调用，只省去通知与轮询；运行时仍执行完整流水等待。
内联候选则保留完整通知和轮询，仅把尾部函数改为`always_inline`。

小用例任务`task_20261011_213347_229363527638`，卡2：
AIC/AIV两种长度、两组输入、输出/fanin/保护区及图重放通过。
AIC loops1两组有6/16条后到交接，loops4有18/23条，重放分别有5/21条。
本轮AIV未观察到交接，不能据此声称内联后AIV重叠已经验证；候选最终因性能回退未采用。

CSA任务`task_20261011_213435_23299425168`，卡0：

| 路径 | min（μs） | mean（μs） | max（μs） |
| --- | ---: | ---: | ---: |
| 普通版 | 961.66 | 982.10 | 1017.08 |
| 单次探测 | 977.92 | 992.43 | 1017.12 |
| 空回调诊断 | 966.60 | 984.52 | 1009.80 |
| 原完整通知（独立尾函数） | 975.12 | 993.74 | 1015.22 |
| 内联完整通知 | 976.96 | 1004.25 | 1024.64 |

内联较原完整通知mean多10.51μs、max多9.42μs，30组仅4组更快，配对差值中位数+9.22μs，
因此不保留。没有机器码级证据将其精确归因于寄存器压力或指令布局，不把猜测写成根因。

空回调较单次探测mean少7.90μs，而完整通知较空回调多9.21μs。
这说明不能简单按函数调用数量推断总耗时；额外探测时机和编译布局也可能改变交接与调度。
它们是完整路径的净差，不是“回调成本为负”或“DMA单项精确耗时9.21μs”的证据。
空回调缩小了持续观察窗口，不能因本轮较快而替换完整方案。

## 第二轮：DMA提交前再看正常派发结果

候选在尾部函数读完通知源、即将提交GM→L1/UB搬运之前，再读一次既有DATA_MAIN_BASE。
若已出现后继则立即返回，由原runtime检查generation/能力并交接；若未出现则继续完整通知与轮询。
不延长人为Scalar循环，不增加派发触发，也不取消末尾完整等待。

任务`task_20261011_214059_258501121711`在卡0依次完成两任务小例子与CSA，退出0。
小例子两种长度、两组输入、数值/fanin/保护区与重放均通过。由既有trace可识别

配对差值中位数+6.05μs。小例子证明能省掉一部分通知，但不足以推导真实CSA总体受益。
该候选同样不接入；没有以功能命中数替代性能验收。

两轮CSA各路径9项输出/缓存/状态与普通PTO逐bit一致，改变输入重放也一致，各31项保护区通过。
这不是Native数值或整模型token验收。所有卡已释放，无16卡或七档重测。
两轮普通基线也有漂移，不将跨轮绝对差值归为某一项优化。
