# O_B 后段 L2 预取候选

## 要缩短的路径

O_B 对 32 MiB 只读 INT8 NZ 权重的供数位于最终输出路径上。原流程先完成
Attention，再执行 O_A、分组量化、O_B 和 HCpost。候选在原
`PHASE_ATTN_VECTOR` 发布后，由四条 AIV 各预取 8 MiB O_B 权重，借 AIC
执行 O_A 的时间把后继读取提前。Attention 源码、数学、FIFO 均不修改。

旧 Q_B 方案在 HC/QA 前段提交，虽局部缩短 Q_B，却延后前段并使完整 CSA
变慢。本候选换了权重、提交时点与重叠区间，且使用新版通道、scratch 与
等待实现；不是原样重跑旧 Q_B 负例。把提交放在 Attention 之后，也避免
先预取的 O_B 权重经过整段 Indexer/Attention 大量访问后再被消费。

## 合同与成本

- 原生 NZ 权重在编排建立完整一维物理字节视图，再在核内按四个连续块切分。
  不新增外部 Tensor 根，不复制权重，不让 host 读取设备 metadata。
- 使用既有长历史 `BALANCED` 策略且动态 `T>=64` 的区间，不列举 batch 点。
- 尾部两组的双 AIV 共四个发起者；新版 runtime 保证驻留通道互不重号。
  48 AIV 的原工作全部保留，不永久占用预取专用核。
- 原 packed 完成通知先发布，AIC 无新增跨核前驱。发起者等待自己的预取
  事件后再进入原量化；等待可与 AIC 的 O_A 重叠，但仍计入完整首尾耗时。
- 新增 SDMA 提交、Scalar 探测、256B UB 保留和额外 L2/HBM 访问。O_A 读取
  与预取仍可能争用带宽或造成缓存淘汰，不能把提前读取的 32 MiB 当作减少
  了 32 MiB HBM 流量。
- `wait=false` 在候选本核独占信号隔离区写失败标记，现有保护检查必须失败。
  不改检查阈值、不将失败解释成取消、不允许继续重放失败工作区。

## 潜在收益和停止条件

只读供数提前能否省满 20 μs 取决于 O_B 的真实暴露读取延迟及缓存保留情况。
32 MiB 除以峰值带宽不能证明该收益；旧 Q_B 的局部缩短也不能外推为 O_B
的收益。因此本候选只安排一次 B16/B28 的配对完整验证，不先扫描发起者数
或块大小。

编译必须确认一个 MIX、动态轴与外部参数合同不变，四份物理范围恰好覆盖
权重，隐藏 scratch 不覆盖业务 Tile，生成代码使用新的驻留通道和等待适配。
功能先检查完整精度、Top-K、cache/state、保护区、图重放和代际。通过后
进行同工具链、同输入的五窗交替 L1 对照。

若未达到一档净省 20 μs 且另一档无明确退步，或任何功能检查失败，不扩档、
不采用正式入口。若有收益，补查实际 L2 命中/缺失及区间边界，再决定采用。
