# 精确 Top-K：成对压缩 score 与索引

## 已有证据与本次差别

设计启动时，短 gather v5 已完成六档严格完整验证。128K/B28 从同轮原单 SPMD 的
1178.64 μs 降至 1157.64 μs，净省 21.00 μs；B16 净省 4.32 μs，
B8 净省 17.52 μs。但是 B4 回退 3.76 μs，B24 回退 2.14 μs，后者
五个配对窗口均慢。8K/B16 基本持平，8K/B32 的原任务仍在队列中。
因此本轮没有把 v5 整体写入正式算子，也不靠单点 batch 白名单隐藏回退。

v5 的实际生成路径先压缩 2048 容量的索引，再补齐索引、物化短索引、
随机 gather score、加全局偏移，最后才 Sort32/MrgSort。
本次拟增加通用的有界成对压缩原语，使用同一比较掩码分别对 score 位表示和
INT32 索引做保序压缩，直接提供二者及真实 count。索引基址作为设备 Scalar
参加整数索引构造，不经 FP32 转换。

## 要缩短的关键路径与成本

目标是 AIV 的筛选到排序之间的串行处理。消除索引补零、短索引物化、
基于索引的随机 gather 和单独的全局偏移加法。比较、计数和排序分支保留。
score 与索引共享比较掩码，但额外增加一遍连续压缩与结果复制；输出 Tile、
scratch 生命周期、内部 V/S 顺序和 UB 容量必须由编译器显式管理。

只用普通 DPS 多输出表示，禁止把 scratch 当作未声明的返回值。
原语返回 source dtype 的 score、INT32 索引以及对齐的 INT32 count。
输出前 `min(count, capacity)` 项有效，尾部未定义，count 仍是真实匹配数。
调用方在排序前将 score 的无效尾部置最小值，只有已经有完整旧 Top-512 根
且阈值高于哨兵时才使用这些结果，因此无效索引不会进入最终结果。
高保留率仍使用原排序；这一情况下额外压缩的成本必须计入完整测量。

可能收益来自减少每叶每查询重复的中间处理，不能把删除的指令数量直接换成
完整 CSA 时间；新增连续压缩也可能抵消收益。本轮不改 score、GE 同分保留、
incoming 优先归并、因果范围、有效长度或 Top-K 数学含义。

## 隔离与验证门槛

使用独立的 `pypto-csa-pair-compact-20261020` 和
`ptoas-csa-pair-compact-20261020` worktree，分别继承已验证的
`65477973` 与 `b48c84eb`，避免改变仍排队的旧候选所用工具链。
Simpler 沿用原隔离版本，共享安装及 pypto-lib 不改。

先检查多输出类型、读写效果、V/S 同步、生成代码及边界拒绝，再复用精确
Top-K 微验证（同分、尾部、零项、超容量、图变输入及保护区）。
通过后只测完整 128K/B16、B28，沿用五窗交替配对口径。
至少一档相对同轮正式单 SPMD 净省 20 μs，另一档无明确回退才扩档。
性能包含所有新增控制与搬运；达不到门槛就停止，不扩大参数扫描。
采用前仍需七档、S1/S5、动态 metadata、边界及图重放证据。

这是待验证候选，不是已获得的收益。最终五档相对多 task 降低 30% 的目标未完成。
