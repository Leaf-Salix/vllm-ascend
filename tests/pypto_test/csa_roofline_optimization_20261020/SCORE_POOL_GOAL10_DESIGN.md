# 10%目标下复核 Indexer WS 列池

优先 128K/B16、B28，B1 的半叶同分修正在另一份候选中独立验证。
正式代码保持不变。本轮全部使用当前 150 tick；公共/多 task 冻结于
`SHARED_SOURCE_GOAL10_B1UPDATE.json`，含刚合入的多 task B1 优化。

## 为什么重评

旧 `csa_critical_path_20261020/score_split_pool` 已通过两档完整精度，
同轮 B16 797.58→792.16 μs（4/5 窗更快）、B28 1175.34→1163.22 μs
（5/5 窗更快）。当时仅因 20 μs 门槛而停止；用户已经撤销此门槛。
本轮不是新算法，差别是采用条件、等待参数、工具链及多 task 基线更新，
需要重新配对，不能把历史 5.42/12.12 μs 直接计入当前优化。

## 缩短的部分与资源约束

保留双 48 KiB QK Acc 提前 FIX；将 WS 的八个 16×64 列窗保存在同一个
32 KiB Acc 池，满 512 列再写回。每 1024 候选的 WS TSTORE 从 16 次减为
2 次，目标是缩短 Score 中小块 FIX 写回的发射与依赖开销。

QK、FP16 舍入、ReLU、K192+192 累加次序、N64 Key 双缓冲、AIV 数学、
READY/ACK 与覆盖保护均不改变。资源仍为两份 48 KiB QK 加 32 KiB WS，
总 128 KiB Acc；只沿既有 SPLIT_SCORE_ROWS 区间，不新增单点特化。

当前没有精确的独占 FIX 耗时，潜在收益以旧两档的几到十余微秒作为
实验依据，不宣称写回次数降八倍就会获得八倍阶段收益。

## 验证和停止条件

使用现有完整 CSA 三方五窗：当前多 task、正式 SPMD、候选 SPMD；
保持精确输出、Top-K/score、状态、保护区、动态 metadata/padding、图
重放及代际检查。地址描述符记录保留，使用独立工作区。

若两重点档均无稳定收益，或一档有明确退步，就停止这个组合，不扫描
更多池宽。不因某一最小值采用。若成立，再覆盖它实际影响的资源区间
及必要 S1/S5 边界；不重复已完成且源码未变的微例。

两任务均completed/exit0，原冻结精确、状态、保护、metadata/padding、图和
代际检查通过，实际两侧150tick核对通过。独立工作区五窗中位数：

|128K/S6|多task|正式SPMD|WS列池|较正式净省|更快窗口|

|B16|840.66|786.66|781.52|5.14μs|4/5|

也不足以证实整体采用收益。B16保留正向证据，整个资源区间暂不采用、
不扩档。没有因取消20μs门槛就忽略波动；后续若收窄，仍须有资源区间
理由和实际边界检查，不能给B16写单点白名单。
