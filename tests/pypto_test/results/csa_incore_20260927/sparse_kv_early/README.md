# Sparse Attention 提前发布KV：核内流水与工作量选择

2026-09-27。性能版候选基于 `daf06ec8`，其中Sparse Attention仍为V10，
KV投影已包含 `21d99f8a` 的B40优化。精度版未改。
先导在所有工作量启用早通知；当前已保留实现改为每核至少6个query时启用，
即 `T >= 24×6 = 144`（S6时B≥24）。小工作量保留原顺序。

## Native策略及事件安全

基底AIV顺序：搬入当前KV → 等上一块Score → softmax → 发布Prob → 发布当前KV → 合并更早PV。
候选顺序：搬入当前KV → 等上一块Score → **发布当前KV** → softmax → 发布Prob → 合并更早PV。
这样允许当前QK与上一块softmax交叠；不修改矩阵维度、候选顺序、BF16量化和归约算术。

Native `sparse_attn_sharedkv_scfa_kernel.h::PreloadPipeline` 在 `ProcessVec0L` 后
立即发布 `syncV0C1`，然后运行上一轮 `ProcessVec1L`。本候选迁移这种发布顺序，
没有搬运Native的512候选分块或改变PTO的128候选算术。

PTO仍先消费上一块Score通知，再允许AIC产生下一个Score；三槽KV/Score/Prob/PV缓冲保持原分配。
当前与上一块的Score槽不同，下一轮KV通知要等本轮softmax完成后才能发出。
有效块条件、事件次数及AIC处理顺序不变。功能检查同时覆盖全有效候选、压缩候选尾块和空块。
跨任务数量、调度依赖、入口拆分及出口写回均未改，属于核内流水调整。

- 五档完整CSA保护区和Top-K结构检查通过，所有张量非有限值0。
  输出max_abs：128K/B16为0.0390625，其余0.03125；逐项RMSE和Top-K差异见 `cases.json`。
  完整CSA开启atomic，不能用不同轮次输出的微小差异代替固定输入的事件顺序检查。
- 独立PMU的qk_pv AIC平均cycles从545378.21降到511270.92，Cube busy从21.23%变为22.65%；
  AIV平均cycles从549963.79降到516639.98，Vector busy从33.97%变为36.31%。
  PMU是一次独立program诊断，各流水交叠，不代替上面的稳态本体结果。
- 零容差对Native仍FAIL；未进行新策略的16卡token/DSpark验收。
