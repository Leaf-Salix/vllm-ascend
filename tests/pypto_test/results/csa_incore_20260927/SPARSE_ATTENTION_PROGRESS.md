# 稀疏注意力核内先导实验（2026-09-27）

三个候选均未取得明确的 CSA 本体收益，已从正式源码撤回，保留 V10 稀疏注意力实现。
只测 8K/B40 代表档，没有扩散到七档、16 卡或改动跨任务调度。
固定正式 layer 4 权重＋合成历史、S6/TP1/mode2/atomic1/确定性0、EPLB关闭，第二层 metadata 复用。
每个候选先检查 CPU kernel ABI 与 AICPU C++ 编译，再做 5 次预热、20 次无 profiler 计时，
独立采集四个 DFX 图重放窗口。Native 与 PTO 本体表列均为各轮实际测量，没有归一化旧数据。

浮点零容差仍为FAIL；这些统计不证明候选与V10逐bit相同，也不是整模型精度验收。

## 从实验得到的限制

1. 单纯把输出N切成128不能得到Native双缓冲。生成C++的四块结果复用同一L0C地址，
   后一块Cube等待前一块FIXPIPE完成；这版核内退化，不保留。
2. 两块累加结果同时存活后，生成C++确认使用不同L0C地址。
   四窗口AIC均值从330.40降为322.63 μs，约2.35%，但范围重叠、主本体计时没有改善。
   当前证据不足以作为正式优化保留，不为追求微小数字重复跑大量样本。
3. 预读索引和页表把热点地址计算中的GM标量读替换为UB `GetValue`，
   但没有降低qk_pv核内时间。本候选独立基于V10，不叠加PV分块。
   原始逐行索引读取不是可以凭代码形式就认定的主要瓶颈。
4. 这些结果只否定本次三个具体候选的保留依据，不证明所有形状或更完整的Native流水都无收益。

## 下一项需要处理的工作量差异

Native源码确认：原始窗口和compressed候选分别按`s2BaseSize=512`计算循环数；
完整128窗口＋512 compressed时为1＋1段。PV在K方向累计结束才写出FP32结果。
当前PTO128分块为1＋4段，每段都写出`64×512` FP32部分结果，再由AIV归并。
仅按逻辑PV结果写入计算，分别约256 KiB和640 KiB/query；差384 KiB/query。
这是逻辑中间结果量，不是测得的DDR流量或已验证收益。

直接改ATTN_K_TILE=512会使当前三槽KV的L1占用超限，且需要调整softmax的UB分块与流水，
不能只改一个常量。精度版已有512分块实现，但其串行交接不能直接当作性能版优化。
后续应联合处理PV部分结果量与核内流水；同时推进长上下文Indexer的4＋2 query复用。
