# 最新QLI V2策略：四路跨分片Top-K归并

首轮已完成，退出0，device10。长档merge核内有明确收益；短档核内及完整层回退，
当前不将这个通用核直接合入。下一版在同一算子内按实际cache长度选择原二路核或四路核，
避免单leaf输入承担多路分支及UB临时量，见[分核候选](../csa_topk_fourway_adaptive_20260928/README.md)。

来源为本地ops-transformer b5b33e14的QLI V2 A3
`attention/quant_lightning_indexer_v2/op_kernel/arch22/quant_lightning_indexer_v2_service_vector_arch22.h::ProcessLD`。
原实现每轮把累计Top-512与三个新分片归并，开启输入列表耗尽暂停，并保留Top-512继续处理。

候选冻结在`.cache/csa-topk-fourway-e58ddc94`，基底生产e58ddc94，只改性能版跨leaf Top-K。
按实际半leaf数H选择四路、三路尾块、二路尾块；同一套代码处理所有batch/seq，H=2走原二路函数。
Score、归约、量化、cache与调度不改，没有叠加前两项sync_start候选。
H−1轮归并降为ceil((H−1)/3)轮；H=8时7→3，H=10时9→3。该数值是操作次数，不是设备收益。

三/四路采用当前PyPTO已有的`exhausted=True`：A3 ISA设置输入列表耗尽暂停。
每个输入均有512对，一旦任何输入耗尽，已经写出至少512对有序结果；只读取/写回这段有效前缀。
临时缓冲仍按全部输入容量分配，不假设暂停时输出长度恰好512；PTOAS/ISA保持现用版本，没有额外修改。
新列表按新到旧放在累计根之前，沿用当前PTO的相等score优先次序，小用例及两档完整层已确认。

与AscendC原写法仍有明确差异：当前保留每个归并组之后的GM根写回，暂不同时引入UB循环携带根；
此前二路UB根候选产生额外完整tile TMOV且没有核内收益。本轮先检验减少归并轮数与耗尽暂停的组合。
ISA仍有V→S状态读取和UB→UB输出复制，不能只按少几次GM访问推算性能。
不引入QLI V2的独立metadata/全核SyncAll，现有PTO依赖图保持。

完整CSA及独立merge探针CPU lowering/PTOAS/CCE/链接通过。
设备任务`task_20260928_125318_172416512553`：先运行五组很小的merge用例，验证2/4/6/8/10份列表，
包含随机相等分数、全相等分数、单列表占优、mask尾部、三路/二路尾块与保护行。
参考由CPU整体稳定排序独立生成，按整数位模式比较score/index，确认不用容差掩盖选择差异。
只有小用例通过，才跑128K/B16及8K/B16整层；各侧20次无profiler图计时、四个独立DFX窗口，
layer4真实权重/合成历史、S6、mode2、atomic0、det0、EPLB关，先比merge核内，再报告完整CSA/P95。
八类状态、保护区、自重放及A→B→A要求精确；未保存idx_topk_scores，专门merge用例另外比较score/index。
五组小用例通过；两档八类PTO状态、保护区、自重放及A→B→A均通过，尚未做真实EP16。
