## 实现与能力边界

Native物理页仍是4096B INT8 key＋64B FP16 scale，页跨度支持现有合同的64B倍数。
PTO根入参只有一个可写Native物理页描述符。Score调度函数内部reshape为字节流，
再以0/64B偏移派生两个128B行宽的GM视图；视图只描述地址，没有device内存搬运。
每个32行页按物理起点模128选视图，直接GM→L1；scale按原页偏移4096读取。
尾页按原逻辑夹到最后有效页，后续有效候选掩码保持不变，不依赖物理页连续。

Compressor只写原Native物理slot，删除逻辑连续cache的双写；量化结果和串行scale保护不变。
删除性能版SplitIndexerCache与其过时CPU用例，不新增缓存分配、PTO task或运行时环境开关。
数学、任务数、调度标志和已保留incore优化不改。

两个外部Torch view与可写Native根入参部分重叠，会被PyPTO `_validate_aliases`拒绝。
最初任务4278912385/4351323022因此退出1，未执行CSA；不能把CPU编译成功说成设备通过。
沿用历史的内部GM视图解决，不放宽检查、不改工具链。视图在Score调度函数内就地构造，
避免JIT对多层inline/constexpr调用传播动态slice元数据的限制。

与上游pypto-lib的差异：此处仍复用Native交错物理页和FP16 scale，需要页表寻址及0/64B选择；
不强行把它解释成请求逻辑连续缓存。相比上一版每lane读384/512连续行，当前按32行页读取，
DMA次数增加；收益必须覆盖省掉的入口Torch复制，不能只报“少搬了一份缓存”。
