动态 Attention：负载均衡收益可能超过调度成本

以 CSA 为例：运行时工作量和就绪时刻会变化；蒸馏为单 SPMD，不能自动保留 MPMD 的全部动态调度能力。

运行时 metadataQ / L、可见范围、压缩块
→
Indexer / Top-K有效候选、页块与就绪时刻
→
Attention不同 query 的有效 KV 工作量
→
各核负载可能不同变长、稀疏 Attention 同样适用

MPMD：运行时继续分配就绪任务

有派发成本

在可调度的任务粒度上，让空闲的同类核接续工作。

worker 0
任务 A任务 D
worker 1
任务 BE
worker 2
任务 CF

工作量变化时，有机会减少尾核拖延与资源空置，
其收益可能抵消、甚至超过动态调度的成本。

单 SPMD：固定归属可能留下长尾

外部派发更少

动态循环仍能变化，但空闲核不会自动接走别核工作。

worker 0
任务 A任务 B任务 C
worker 1
任务 D空闲 / 等待
worker 2
EF空闲 / 等待

省下任务交接，同时可能增加负载不均和内部等待；
减少调度开销，并不等于完整 L1 更短。

动态计算 ≠ 动态调度

单 SPMD 可保留动态长度、索引和循环。
运行时将就绪任务重新分配给空闲核，
是另一项调度能力。

从 CSA 扩展到 Attention

遇到变长、稀疏和数据相关的工作量，
MPMD 可能更适合保持负载均衡。
最终仍须在目标场景实测比较。

AOT / 常驻执行仍是一种选择

稳定子图可继续扩大并固化为 Engine Kernel；
需要动态平衡的区域，也可保留 MPMD。
静态化范围由收益和动态性需求共同决定。

动态负载均衡收益 与 任务派发成本 的权衡，决定保留 MPMD，还是蒸馏为单 SPMD。

两侧使用同一组 A–F 工作量，仅示意固定归属可能造成的长尾，非实测泳道。MPMD 按就绪任务派发，不表示可抢占已运行的 task。
