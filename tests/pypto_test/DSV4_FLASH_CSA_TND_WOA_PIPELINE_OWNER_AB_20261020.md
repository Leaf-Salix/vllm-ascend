# TND精度SPMD后缀：WO-A搬运、流水及owner增量对拍（2026-10-20）

## 结论

以“WO-A→BF16只等实际8个owner”的phase1版为起点，本轮找到三个有效的实验方向：

- T240/T256把WO-A搬运粒度从K256改为K128，保留实际MMA顺序，分别降低4.80%/3.64%，每档12/12窗改善。
- T126/T96把尾段heads一次搬入L1，保留15次K16累加，分别降低10.00%/7.05%，每档12/12窗改善。
- BF16→量化只等实际8个生产者，T126/T240分别降低11.63%/5.89%，每档12/12窗改善。

组合没有达到正式接入条件：T126组合仍慢于同任务冻结后缀16.46%，T240组合仍慢6.54%。
所有12项正式AB均通过五边界逐位检查，但没有候选稳定快于冻结后缀；不改正式路由，不进入8K/128K整模型门禁。
尾段权重也驻留L1反而回退2.80%，移除stage2预取回退2.49%，均不保留。

本轮16项单卡任务全部结束，13项exit0、3项观测脚本失败；没有遗留任务。
失败细节、CPU未通过的尝试及原始设备数据一并保留。

## 对照nalinaly及实际生成物

| 方面 | nalinaly参考 | 当前精度后缀及本轮验证 |
| --- | --- | --- |
| WO-A K轨迹 | 顺序K256，按形状组织SPMD及局部驻留 | Native校准的cyclic K轨迹；不能直接换成递增K而声称精度不变 |
| 量化 | 1024列分组scale | 8192列共同amax/scale及BF16边界；本轮不改数学 |
| 依赖 | 按真实owner推进 | 起点phase1已缩WO-A→BF16；本轮独立缩BF16→量化 |
| 搬运策略 | 分级缓冲和预取 | 逐项核实L1/L0地址、实际MMA和事件，不以源码stage=2替代真实流水证据 |

T126与T240走不同WO-A路径，不能混为同一个流水问题：

1. T126为K16 seed、15个K256 packet、15个K16 tail。packet内部跨界时维持原16次K16次序。
2. T240为seed_fast：K256 seed及后续15个K256 packet，实际每K256降为两条有序K128 MMA。
3. 原T240生成码中L1已有双缓冲，不能称为“预取完全失效”。L0A/B的两个槽已被内部两条K128占用，跨packet复用存在序列化约束。
4. K128候选的L0A/B实际各有0/32768两个32KiB槽，Acc为同址64KiB；L1地址0/32768/65536/131072，高水位160KiB。事件及loop drain经独立生成码审查。
5. T240/T256目标起点均same-start且16对齐，全部进入新快路径。其它起点保留原M16回退，不能推广为所有T、所有起点均获益。

低T heads-tail驻留把15条heads GM加载合成一次K256，消费者仍按原15次K16执行。
它减少加载命令，**名义数据量由K240变K256，略增6.67%**，不能叫搬运字节量下降。
独立Mat控制版单独测过，避免将表达方式变化误记成驻留收益。
权重驻留候选最终生成TEXTRACT(full Mat[256,128])，父NZ步幅正确，未出现缩窄descriptor错位；硬件仍回退。

owner2只删无关等待，全部publish、payload cache维护、barrier及数学保持。
T1..256依赖已穷举：量化所需8个cast owner的WO-A依赖并集仍覆盖全部24 AIC，
因此不能解释为“量化已提前与WO-A重叠”；减少无关cast等待及轮询是待进一步区分的机制。

## 测量方法

- 先无设备完整PTOAS/CCEC编译和artifact.load，检查实际布局/容量/事件，再提交NPU。
- 三臂同卡同输入：冻结PTO、**本行明确父版**、新候选；resident键不总等于phase1。
- 先检查projected BF16、quantized INT8、token_scale FP32、attended BF16、最终output BF16五边界。
- eager及FULL A/B/A毒化写回、只读SHA、输入/工作区/signal guard、独立地址与双代际；首差即停。
- 正式计时不插桩：12窗×100次FULL replay，三臂位置轮换/反转，不删离群值；每窗后再次逐位检查。
- 每项160个逐位指标、双generation1204均通过。中位数是12个窗口平均耗时的中位数，并非单次p50。
- L1 DFX与CANN PMU分别独立任务，不开dep-gen；每arm三次单回放，不能替代正式连续回放排名。
- 每任务内750秒、调度780秒；本轮正式AB的probe运行92.1～108.0秒。任务结束状态保存在证据中。

## 补充控制：合并行面板复用WO-A权重

T240原先有两个M128行面板，目标校准起点在全部真实行上相同；M256可让同一权重panel服务两倍行。
原M256 stage2在CPU即因Left131072B超过65536B失败，未上卡。保留失败源与v10回执。
为隔离M维影响，v11设M128/K128 range控制及M256/K128 range候选，二者都取消该循环的双缓冲。
这项增量只比较同为range的M128/M256，不能直接当作M256相对K128 stage2的单因素结论。

CPU完整PTOAS/CCEC与artifact.load双臂通过；实际M256 Left64KiB、Right32KiB、Acc128KiB，均为单槽。
K128 init及31次K128 acc原序保留，MTE2/MTE1/M/FIX复用依赖完整；valid=min(256,真实行数-row)贯穿load/store。
192..256行覆盖和所有标定起点穷举通过；T240父版128个快路径任务变64个，无回退。
Vector及WO-B与父版不变，属于WO-A行复用控制；硬件结果另列，不能仅凭源级搬运减少宣布收益。

## 失败历史及决策

CPU v1/v2的NZ偏移证明、v3/v4的L0C条件合并、v6的load参数顺序均在设备前拦截；
没有修改SDK或放宽证明器。原样源码快照、日志和结果均保留。
低T split/range、split/pipeline没有完整编译资格，未上卡，不当作硬件精度失败。
DFX首次因不存在的DfxConfig API失败，第二次因重复初始化配置冲突失败；第三次恢复实际init接口成功。
当前probe已加单次init AST和签名门禁、F821检查；不删除失败任务。

当前保留的是独立实验方向：owner2、heads-tail、K128及其组合，不替换正式冻结后缀。
取消预取、完整tail权重驻留和此前无收益组合不推广。
下一轮需要分离主packet的控制/搬运气泡与真实依赖轮询竞争，并首先取得对冻结后缀的净收益；
这些仍是待测解释，不能直接视为已确认瓶颈或已解决问题。

完整CSA稳定更快后，才能先8K/B40再128K/B24做192-token Native一致性门禁。
本轮未新增整模型token或Native直接逐位资格，原精度基准和历史验收范围不变。
