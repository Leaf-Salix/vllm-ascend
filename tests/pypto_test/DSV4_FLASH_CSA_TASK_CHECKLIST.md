## 1. 最终交付与验收合同

### 1.1 目标

1. 正式 W8A8 模型的 PTO 接入功能正确，支持当前声明的 decode、padding 和 ACL Graph 场景。
2. 保留精度版、性能版两个入口；共用适配及数值中性实现，明确隔离算术差异。
3. 精度版尽力对齐 Native 的规约规则、量化顺序和舍入；不把完全 bit 一致作为无条件目标。
4. 性能版允许采用 pypto-lib 的精度策略，但必须独立通过逐元素、状态和整模型验收。
5. 最终 PTO 整模型表现必须明确优于 Native，且性能版
   **HC_pre → norm → CSA → HC_post 完整设备区间 <750 μs**。
   原单卡泳道 ≤725 μs 仅为优化参考，不再作为最终验收线。
6. 四张目标权重 `wq_a / wq_b / wo_a / wo_b` 的 NZ 都继续推进；
   编译限制须先在算子侧寻找解法，未实现不能写成完成。
7. mode=1、mode=2 均评估后选定性能更好的主口径；ND 独立实现与回归入口长期保留。

750 μs 的确认口径：B16、S6、TP1、EP/DP16、H8192、FULL_DECODE_ONLY；
统计各 CSA 层稳态完整设备区间的中位数，并报告 p95、rank/层分布。
该区间含内部间隙与必要适配，不用各 kernel 耗时相加代替。
最终主对照两侧使用相同 mode，各测 mode=1/2 后选定主口径，保留另一档结果。

### 1.2 功能错误与精度权衡分别处理

| 类型 | 判据与处理 |
| --- | --- |
| 功能错误 | 错误布局/stride/offset、越界、漏写、错误 metadata、陈旧状态、未声明回退、非有限值、错误同步均必须修复，不得靠容差掩盖 |
| 精度版算术 | 对齐 Native 规约、量化顺序及舍入；逐元素报告差异，区分固定实现差异与运行间波动 |
| 性能版算术 | 可以采用 pypto-lib 策略；逐项注明与精度版的差异、适用范围和误差证据 |
| 整模型 | 必须逐 token 一致，同时检查真实 DSpark 草稿数、接受数/长度及层级误差 |
| metadata 与保护区 | 长度、页号、slot、掩码等整数/索引逐元素精确一致；不得写的区域保持不变 |
| 浮点 cache/state | 每种状态单独明确有效范围、atol/rtol、误差统计及参考来源，未定标准不能 PASS |
| 量化 INT8 / Top-K | 允许符合明确量化/选择/tie 规则的差异，前提是逐元素误差受控、逐 token 和 DSpark 统计一致；规则须在验收前明确，不把它们与 metadata 索引混为一类 |
| 非确定性 | 先量同输入重复执行的逐元素误差，再比较实现之间的误差；不能以 mean/absmax 相同替代数值验收 |

现有 BF16 `atol=1e-2, rtol=1e-2` 仅是旧单层输出标准的参考，
不得直接套用 mHC 残差流、所有中间量或全部浮点状态。
门槛须先与对象和算法对应，再用于新实验；失败后不得自动放宽。

  版本确认与升级策略落在 A4，不先重装整个环境。
- 现有 Native 扩展和 custom OPP 已具备，除非具体失败指向它们，不重复编译。

### 2.2 不过度校验与测试

- 不新增 hash/摘要扫描；使用版本标识、明确路径、文件大小和必要数值比较记录证据。
- 不自动全量测试、格式化或运行提交钩子；文档修改不占卡。
- 先 CPU 检查可在 CPU 判定的问题。**所有测试尽量先构造单卡 case，
  在单卡完成复现、调试和受影响项验证，再做真实权重 16 卡测试**，
  避免把反复启动整模型作为日常调试手段，减少测试调试时间。
  单卡 case 可使用合成输入、最小权重或已有单层快照，保留问题涉及的形状、布局和状态语义。
- 只有无法在单卡表达的多卡通信或整模型行为，才直接做必要的 16 卡验证，并说明原因。
  单卡结果用于定位和筛选候选，最终仍以真实权重 16 卡整模型验收为准。
- 首轮覆盖代表档位、尾块、padding 和长短上下文；
  阶段出口才补齐全部声明支持的档位，复用未受影响的有效证据。
- 性能采样尽量在一次启动内完成预热和多次稳态采样；
  只有噪声妨碍结论、新失败或新增改动时才扩大测试。
- 所有 NPU 测试走 `task-submit`。只操作本任务提交的任务，不停他人任务。
- 排队状态使用 `task-submit --status <id>`，不用会取消排队任务的 `--wait`。
  模型任务显式设置足够的 `--max-time`，不能沿用默认 300 秒。
- 排队或运行中的任务使用固定源码；冻结目录或独立 checkout，
  不在其 JIT 可能读取的文件上继续编辑。
- 产物放 `tests/pypto_test/results/`；不提交权重、张量大文件、
  二进制、安装包或重复编译目录。只精确暂存目标文件。
- 中文沟通、提交说明及新增说明性注释；提交带 `Signed-off-by`。
  清单重构单独提交，之后每个可独立验证的修复/优化单独提交。
- 按依赖自主推进，阶段完成汇报；涉及验收放宽、范围变化等重大取舍再讨论。

### 2.3 状态定义

`待做`、`进行中`、`待设备验证`、`已验证`、`阻塞`、`暂停`。

只有完成该项全部出口判据才写“已验证”。
编译通过、程序退出 0、仅测性能、未采到样本分别记录，不能统一写 PASS。
失败必须返回失败状态/退出码；缺证据记录未验证，不用估算值补齐。

- 旧 T2.31/T2.32 的“mode=1 整模型已验证”：`--weight-nz-mode` 未传给 rank，
  `perf_mode1_20260925/native/rank0.log` 与 `pto/rank0.log` 实际均记录 mode=0。
- 旧 T6.1.2 的“wo_b NZ 无收益”：当时根布局仍为 ND，目标路径没有生效。
- 用 `absmax/mean` 相同推出“输出逐位相同”或“NZ 未改变任何数值”。
- 将最新两轮 833.8 μs 直接当作稳定性能基线或生产达标结论。
- 由 scheduler/worker 重复计数、混用源码版本或把 local_setup 当计算时间得到的归因。

旧历史留在 Git；不删除原始失败产物，不把旧文件改写成新结果。

```text
A1 配置贯通 → A2 数值门禁 → A3 回放合同 → A4 工具链核对 → A5 可信基线
                                                        ↓
                    B1 确定性诊断 / B2 精度对齐 / B3 性能精度策略

                                                        ↓
```

所有阶段的测试均遵循 2.2 的单卡优先顺序，再进入真实权重 16 卡验证。
A 阶段完成后必须继续 B/C/D，不能只修工具就结束整个目标。

### A5 建立可信的精度和性能基线

1. 先构造或复用单卡 case，覆盖 A1～A4 受影响的路径，完成定位和验证；
   再使用已固定的正式权重进行 16 卡测试，输入与初态来源明确，覆盖两版入口。
   主场景 B16/S6/H8192，先校验真实执行配置。
2. 最小重复运行观察自身稳定性；必要时再扩样，不机械重复启动大模型。
3. 以逐元素比较建立两版/Native 的误差表；未归因功能错误先修复。
4. 精度诊断开启 Native 确定性；性能使用部署配置，记录两侧开关。
5. 采完整设备区间及稳态 decode 指标，排除加载、编译、IO、额外对照开销。
6. 图模式确认实际 PTO 命中、无静默 Native 回退；诊断 hook 必须有有效样本。
7. A1～A4 设备验证尽量合并到这一轮，不为各项单独重复 16 卡启动。

**出口**：baseline 含配置、版本、逐元素结果、状态、样本和测量范围，
能够支撑后续同输入 A/B；尚未达到最终性能目标不妨碍基线成立。
**产物**：`results/<本轮目录>/baseline/`。
**依赖**：A1～A4。**占卡**：单卡优先，整模型 16 卡。**状态**：待做。
